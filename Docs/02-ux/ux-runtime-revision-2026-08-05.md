## 1. 冻结事实与术语

- 只使用 MiPlay 托管 Wine。官方 GitHub 是默认来源，用户只能主动选择预置可信镜像，不能输入 URL、token 或 allowlist 外来源。
- 系统 Wine、Whisky、CrossOver 不检测、不展示、不导入、不复用，也不作为失败后的 fallback。
- **可用版本**：批准来源目录中可以作为获取目标的版本条目；不代表本机已有安装。
- **下载目标**：正在获取的版本；不代表已安装或已选中。
- **已安装版本**：MiPlay 管理范围内安装完成、托管可执行文件身份可复核、安装记录重读一致的版本。
- **当前选中版本**：已安装并绑定到一个 Game ID 的版本；下载目标不会自动覆盖此前有效选中版本。
- **当前运行时**：当前 Game ID 的选中版本身份、来源、安装事实和该游戏 readiness 的组合。它不是全局机器状态，也不是任意 `wine` 文件。
- **`WineReady`**：当前选中版本对当前游戏通过运行环境准备和启动前置校验。只有此结果才具有启动语义。

下载进度达到 100%、文件存在、解压目录存在或命令输出文本，都不能单独产生“已安装”或 `WineReady`。

## 2. Wine 设置页信息模型

Wine 设置只管理托管运行时，不与三款游戏的独立设置混合。信息分为四个彼此可区分的状态区域：

1. **当前运行时**：始终带当前 Game ID；显示名称、版本身份、来源、安装状态、选中状态和 readiness。
2. **可用版本**：当前选定来源返回的可获取目录；显示来源和目录状态，不显示成本机安装。
3. **已安装版本**：MiPlay 管理范围内已验证的本地版本；不因远程目录刷新而消失。
4. **当前任务**：下载、安装、删除、切换或恢复中的目标、阶段、进度、速度和恢复动作。

“当前运行时”没有当前游戏、没有选中版本或 readiness 未通过时，必须显示对应未就绪事实。单独显示一个 Wine 名称、版本或路径都不算当前运行时成功。

### 2.1 当前运行时状态

| 状态 | 准确文案 | 用户动作 | 终态定义 |
|---|---|---|---|
| 无当前游戏 | “请选择要查看运行时的游戏” | 选择一款游戏 | 不产生全局运行时结论 |
| 无选中版本 | “{游戏名}没有选中的托管运行时” | 获取或选择已安装版本 | `NoSelectedRuntime`，阻止启动 |
| 选中但未就绪 | “{游戏名}的运行时尚未就绪” | 查看原因并重试准备/恢复 | `SelectedNotReady`，阻止启动 |
| 正在下载目标 | “正在下载{版本}；当前运行时保持不变” | 查看进度或取消 | 下载目标不是选中版本 |
| 正在安装目标 | “正在安装{版本}；当前运行时保持不变” | 等待或按规则取消 | 安装提交前不是已安装 |
| 已安装但未选中 | “{版本}已安装，尚未用于{游戏名}” | 选择该版本 | `InstalledNotSelected` |
| 已选中且就绪 | “当前运行时：{版本}；{游戏名}已就绪” | 启动游戏或切换版本 | `WineReady`，允许启动前置流程 |
| 不可用 | “当前运行时不可用：{原因}” | 按原因改选、重试或等待修复 | `RuntimeUnavailable`，不提供启动语义 |
| 需要恢复 | “运行时状态未确认，当前不能继续操作” | 先完成恢复/清理 | `RecoveryRequired`，阻止同目标新任务 |

### 2.2 可用版本与已安装版本

| 区域 | 空 | 加载中 | 成功 | 失败 | 不可用 |
|---|---|---|---|---|---|
| 可用版本 | “所选来源尚未返回版本” | “正在检查{来源}版本” | “找到可获取的托管版本” | “版本源查询失败：{来源}/{原因}” | “当前没有可获取的托管版本” |
| 已安装版本 | “尚未安装托管 Wine” | “正在读取已安装版本” | “已找到{数量}个已验证版本” | “无法读取已安装版本，安装状态未确认” | “当前没有可验证的已安装版本” |

远程目录为空是成功取得目录后的 `noAvailableManagedVersion`，不是网络失败。已安装列表读取失败时保留上一次已验证结果并标记过期，不把空列表当作“没有安装”，也不删除已有当前选中事实。

如果远程目录刷新后不再列出某个本地已安装版本，仍保留“已安装但当前来源未列出”的本地事实，并标记该版本当前不可重新获取；不能自动删除、隐藏或把旧版本改写成新目录结果。未经重新确认前，该版本不能产生新的 `WineReady`。

## 3. Wine 来源、下载与安装状态流

```text
选择官方 GitHub 或预置镜像
  → 查询来源目录
     ├─ 有可获取版本 → 可选择下载目标
     ├─ 有效空目录 → 没有可获取版本
     ├─ API 403 → 所选来源拒绝访问
     ├─ 网络/超时/限流 → 来源网络失败
     └─ 格式或来源身份无法确认 → 版本源信息不可验证
  → 下载目标 pending/running
     ├─ asset 被拒绝/不可取得 → 下载失败，不覆盖旧版安装/选中事实
     ├─ 下载失败或取消 → 不覆盖旧版安装/选中事实
     └─ 传输完成 → 安装中
  → 安装、托管可执行文件复核、记录提交和重读
     ├─ 成功 → 已安装但未自动选中
     ├─ 可执行文件找不到/身份不一致 → 安装失败
     └─ 提交、清理或恢复未确认 → recoveryRequired
```

### 3.1 来源查询反馈

| 事实 | 用户文案 | 恢复动作 | 终态 |
|---|---|---|---|
| 首次查询 | “正在检查{来源}的托管 Wine 版本” | 等待或取消 | 查询中，不是空列表 |
| 官方 GitHub API 403 | “官方 GitHub 版本源拒绝访问（403）” | 稍后重试或主动选择预置镜像；不提供 token | 来源拒绝访问；不显示为空 |
| 预置镜像 API 403 | “所选镜像版本源拒绝访问（403）” | 稍后重试或改选其他预置来源 | 来源拒绝访问；保留镜像身份 |
| 来源网络失败 | “无法连接所选{来源}版本源” | 恢复网络后重试或主动改选来源 | 网络失败；不显示为空 |
| 有效空目录 | “当前没有可获取的托管 Wine 版本” | 稍后重试或等待 MiPlay 提供版本 | `noAvailableManagedVersion` |
| 来源信息无法确认 | “版本源返回的信息无法确认” | 稍后重试；保留诊断事实 | `catalogInvalid` |
| MiPlay 来源配置错误 | “托管 Wine 版本源配置错误” | 更新 MiPlay 或等待修复；不要求用户输入 URL | `sourceConfigurationError`，不显示为空 |
| 目录成功 | “找到可获取的托管 Wine 版本” | 选择版本并开始下载 | 只产生可获取目录，不是已安装 |

同一来源失败不自动切换来源。用户主动改选预置镜像后，新的查询使用新的来源身份；任何失败都不能回退到系统 Wine。

### 3.2 下载与安装反馈

| 阶段/结果 | 用户文案 | 恢复动作 | 对旧事实的影响 |
|---|---|---|---|
| `pending` | “已提交下载{版本}，等待执行” | 等待或在未开始时取消 | 不改变已安装/当前运行时 |
| `running` 下载中 | “正在下载{版本}” | 查看阶段、速度、进度或取消 | 不改变已安装/当前运行时 |
| 资源下载失败 | “下载{版本}失败，未取得完整资源” | 重试同一来源或主动改选来源 | 保留此前有效版本 |
| asset 被来源拒绝（403） | “下载资源被所选{来源}拒绝（403）” | 稍后重试或主动改选来源；不提供 token | 保留此前有效版本 |
| 用户取消 | “下载已取消，未安装{版本}” | 清理确认后重新提交 | Task `cancelled` 仅在清理确认后成立；旧版本保持有效 |
| 安装中 | “正在安装{版本}，尚未确认可用” | 等待或按规则取消 | 不进入已安装列表 |
| 托管可执行文件找不到 | “安装失败：未找到托管运行时可执行文件” | 清理未完成内容后重新下载；必要时改选来源 | 不进入已安装/选中集合 |
| 身份或安装记录无法确认 | “安装失败：运行时安装状态无法确认” | 重试安装或恢复；确认前不能启动 | `InstallFailed` 或 `RecoveryRequired` |
| 安装成功 | “{版本}已安装，尚未选中” | 用户明确选择目标游戏 | `InstalledNotSelected` |
| 当前游戏准备失败 | “{版本}已安装，但{游戏名}运行环境未就绪” | 查看该游戏 readiness 原因并重试 | 保留已安装事实，不显示 `WineReady` |
| 删除/切换失败 | “未能完成{版本}的{操作}，当前运行时保持不变” | 重试或恢复 | 保留旧选中版本和恢复事实 |

下载完成不是安装完成；安装完成不是选中；选中不是 readiness。失败、取消或恢复中的新目标都不能覆盖此前可验证的安装和当前运行时。

## 4. 下载期间稳定的进度与速度语义

下载状态必须固定绑定到一个目标：来源、版本和资源名称在本次任务中不改变。展示区域保留稳定的语义字段，不因阶段切换创建/删除整块内容，也不把动态错误文案替换主标题。

| 字段 | 可确认时 | 不可确认时 | 规则 |
|---|---|---|---|
| 阶段 | “下载中”“安装中”“正在确认安装” | “阶段未知，状态仍在确认” | 阶段变化不改变目标版本 |
| 进度 | 真实百分比 | “进度未知” | 不用时间或动画估算；未知总大小不伪造百分比 |
| 速度 | 当前目标的近期传输速度 | “速度未知” | 没有连续样本时不显示 0 代替未知 |
| 已传输/总量 | 真实已传输量和已知总量 | “总大小未知” | 不把目录元数据或旧任务数值复用到新任务 |
| 可取消 | “可取消”或“正在清理，不能取消” | “取消状态未知” | 取消请求不等于取消完成 |

下载期间只更新字段值和阶段事实；不反复替换“正在下载{版本}”“速度…”等主文案，不让失败提示、速度变化或进度更新改变内容的语义位置。VoiceOver 不逐次播报速度采样，只在阶段、可取消性和终态改变时播报。

## 5. 刷新与任务状态流

刷新是读取当前事实的动作；下载、安装、删除和切换是有副作用的任务。刷新不能代替任务终态，也不能在任务进行中创建第二个同目标任务。

| 触发 | 刷新内容 | 允许条件 | 结束语义 |
|---|---|---|---|
| 页面首次打开 | 当前来源目录、已安装列表、当前游戏 runtime | 每个读取目标只启动一次 | 成功、空、失败或不可用均结束 busy |
| 用户手动刷新 | 当前选定来源目录和已安装列表 | 同一读取正在进行时复用/忽略重复触发 | 新一次读取有独立结果 |
| 下载完成 | 目标版本安装列表和当前任务/选中状态 | 仅在下载任务出现终态后触发一次 | 安装中与已安装必须继续区分 |
| 安装完成 | 已安装列表、目标版本选中状态、当前游戏 readiness | 安装提交重读后触发一次 | 只有重读成功才显示已安装 |
| 删除版本 | 已安装列表、当前选中版本和 readiness | 删除清理确认后触发一次 | 删除失败保留旧事实并显示恢复 |
| 切换当前版本 | 目标 Game ID 的选中版本和 readiness | 选择提交后刷新该游戏 | 不刷新或覆盖其他游戏 |
| 网络失败后重试 | 失败的同一来源和同一查询目标 | 用户主动触发 | 不创建隐藏自动循环 |

刷新规则：

- 同一目标已有进行中的读取时，不重复启动、不清空已有结果、不重置进度；用户看到“正在更新”。
- 旧请求返回时，如果目标来源、Game ID 或操作已变化，旧结果只作为诊断，不覆盖新结果。
- 每次刷新最终必须离开 busy：成功、空、失败、取消或不可用都要有终态；超时/取消也不能永久显示加载。
- 任务失败或取消后，可以保留上一次可信目录、已安装版本和当前运行时，并明确标记它们不是本次新结果。
- 下载/安装任务的 `pending/running/completed/failed/cancelled` 不被刷新改写；`RecoveryRequired` 只是保护事实，必须先恢复再允许同目标任务。

### 5.1 Task 状态与 Wine 业务结果

Task 状态只回答任务生命周期，业务结果必须同时回答目标是否真正改变：

| Task 状态 | 用户事实 | Wine 业务边界 |
|---|---|---|
| `pending` | “已提交，等待执行” | 不代表下载、安装或选择已经开始 |
| `running` | “正在执行{阶段}” | 不代表目标已改变；进度和速度只能使用同一目标的真实值 |
| `completed` | “{阶段}已完成” | 只表示当前 Task 自己的成功门槛通过；下载阶段完成仍可能只是进入安装/确认，不得写成已安装或 `WineReady` |
| `failed` | “{阶段}失败：{原因}” | 目标未达成或结果无法确认；保留此前有效安装和当前运行时 |
| `cancelled` | “{阶段}已取消，清理已确认” | 只在必要清理/恢复完成后成立；不能覆盖此前有效事实 |

## 6. “此 Mac”信息模型

“此 Mac”是通用设置中的只读信息组，与 Wine 目录和游戏 readiness 分开。它不展示序列号、平台 UUID、UDID、完整路径或其他非必要设备标识。

### 6.1 信息层级

| 层级 | 字段 | 用户语义 | 禁止推断 |
|---|---|---|---|
| 硬件 | 用户可读机型名称 | 系统报告提供的 machine name，例如 MacBook Pro | 不从 model identifier 拼出尺寸或营销后缀 |
| 硬件 | model identifier | 系统型号标识，例如 MacBookPro18,1 | 不当作芯片名称或屏幕尺寸 |
| 硬件 | 芯片名称 | 系统报告提供的 chip name，例如 Apple M1 Pro | 不从 model identifier 推断芯片 |
| 硬件 | 内存（若系统报告提供） | 系统报告的物理内存 | 不用默认值补齐 |
| 系统 | macOS 产品版本 | 面向用户的系统版本，例如 27.0 | 不用 build number 替代产品版本 |
| 系统 | build number（可展开查看） | 系统构建事实，例如 26A5388g | 不把 build number 显示为产品版本 |
| 磁盘 | Wine 管理目标卷可用/总空间 | 与 MiPlay 托管 Wine 下载、安装目标相关的卷 | 不固定假设为根卷，不使用无关卷数据 |

### 6.2 设备信息状态

| 状态 | 用户文案 | 恢复动作 | 终态 |
|---|---|---|---|
| 加载中 | “正在读取此 Mac 信息” | 等待或取消 | busy 结束后进入明确结果 |
| 成功 | “此 Mac 信息已更新” | 查看字段 | 记录字段来源和读取时间 |
| 字段未知 | “{字段}未知” | 手动刷新或等待系统提供 | 不用其他字段替代 |
| 检测失败 | “无法读取{字段}” | 手动刷新；必要时导出日志 | 不用旧值、0 或空值伪装当前值 |
| 权限/目标不可用 | “无法读取目标磁盘空间” | 等待卷可用或重试检测 | 不要求无关的用户路径授权，不改变 Wine readiness |
| 过期 | “显示的是上一次已确认的{字段}，等待更新” | 刷新 | 旧值不能标记为当前实时值 |

磁盘空间必须描述 Wine 管理目标所在卷。预检查只是信息提示；真实下载/安装仍可能因空间变化失败，失败后按下载或安装恢复流处理。

## 7. 无障碍与键盘语义

Accessibility Tree 使用 Domain/ViewModel 的结构化状态投影，不从视觉状态、空白列表、动画、颜色或布局变化推断。

| 对象 | Label / Role | Value / Hint | 动态播报 |
|---|---|---|---|
| 当前运行时 | 状态对象：“{游戏名}当前运行时” | 版本、来源、选中状态、readiness、可用动作 | 选中/就绪/失败/恢复改变时播报完整事实 |
| 可用版本 | 列表项：“可获取的托管 Wine 版本” | 来源、版本、可获取/不可用 | 403、空目录、网络失败分别播报 |
| 已安装版本 | 列表项：“已安装的托管 Wine 版本” | 安装状态、是否选中、是否可用于当前游戏 | 安装确认和选中提交后播报 |
| 下载任务 | 进度对象：“下载{版本}” | 阶段、进度或进度未知、速度或速度未知、取消状态 | 不逐次播报速度；阶段和终态变化时播报 |
| 此 Mac 硬件/系统 | 只读状态组 | 字段名、值、来源状态或未知 | 读取成功/失败时说明具体字段 |
| 磁盘空间 | 只读状态对象：“Wine 目标磁盘空间” | 当前/总量或未知、读取状态 | 不把 0 或空值读作空间为零 |
| 错误恢复 | 状态对象 + 唯一动作 | 失败阶段、是否保留旧版本、恢复动作 | “当前运行时保持不变”或“当前不能继续”必须可读 |

键盘流程保持稳定：来源选择、刷新、版本选择、下载取消、重试、安装恢复和当前版本切换均可聚焦并使用 Return/Space；同一读取进行中，刷新动作保持可识别但不重复启动；不可用动作说明原因。切换 Game ID 后，当前运行时和 readiness 的焦点目标随 Game ID 更新，不能读出另一款游戏的值。

## 8. Issue 逐条验收

| Issue | 本稿结论 |
|---|---|
| `DL-001` | §4 固定目标、阶段、进度、速度和取消字段；刷新不清空或重建状态区域，不用动态文案改变语义位置 |
| `DL-002` | §4 区分真实进度、未知进度、真实速度和未知速度；阶段和终态来自同一下载目标 |
| `DL-003` | §3.2 把托管可执行文件找不到定义为安装失败；不进入已安装、选中或 `WineReady` |
| `INFO-001` | §1、§2.1 将当前运行时定义为当前 Game ID 的选中托管版本及 readiness |
| `INFO-002` | §2.2、§5 区分可用/已安装/选中；目录刷新不删除本地事实，刷新有去重和终态 |
| `INFO-003` | §6 分开机型名称、model identifier、芯片、macOS 产品版本和 build number |
| `INFO-004` | §6 规定目标卷空间、未知/失败/权限不可用语义，不以 0 或无关卷替代 |
| `STRUCT-001` | §3、§5 分开下载、安装、选中、readiness、刷新和恢复 |
| `ARCH-001` | 本稿不规定实现拆分；下游保持相同状态语义并遵守既有单文件约束 |

本补充稿没有新增 Product 功能，没有把 Research 观察到的旧版路径或失败行为当作产品成功，也没有改变托管 Wine-only 边界。
