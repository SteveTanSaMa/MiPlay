# MiPlay 异常路径与边界情况

> **文档状态**：活跃（Active）
> **UX 阶段**：Edge Cases / Error Flow
> **更新日期**：2026-08-03
> **继承自**：Product Features、Product Domain、UX State Flow、Architecture Communication

> **运行环境后续口径**：2026-08-05 起，Wine 设置、下载、安装、当前选中版本和 readiness 以 [ux-runtime-revision-2026-08-05.md](ux-runtime-revision-2026-08-05.md) 为准；本表中的终态不得把 Task `failed` 简化为“已完成”或把失败提升为 `WineReady`。

## 处理规则

- 先确认是否产生副作用，再决定是失败、取消还是回滚完成。
- “不可用”表示当前不能开始该动作；“失败”表示已经尝试但未达成目标；“不支持”表示校验无法作出完整性结论；“已损坏”表示校验得到了可信的负面结果。
- 自动恢复成功也不改变原任务的失败性质：兼容方案应用失败并回滚后，结果是 `failed + RolledBack`，不是 `completed + Applied`。
- 失败后只提供与当前前置条件匹配的恢复动作；不提供无限自动重试。

## P0 启动、进程与运行环境

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 启动请求刚提交 | “已提交，等待执行” | 取消或等待 | task `pending` |
| 启动任务排队 | “已加入队列，尚未启动” | 取消或等待前序任务 | task `pending` |
| 前置文件不存在 | “启动前检查未通过：找不到游戏文件” | 重新选择路径 | task `failed`，不进入 `Running` |
| 路径可读但完整性损坏 | “完整性校验未通过：发现缺失或损坏文件” | 官方修复/更新后重新校验 | `IntegrityFailed` |
| manifest 缺失/为空/版本不匹配 | “无法确认完整性：当前版本没有可用校验清单” | 稍后重试或使用受支持版本 | `IntegrityUnsupported` |
| 运行环境未安装/未就绪 | “游戏运行环境尚未准备好” | 先准备运行环境 | 启动任务 `failed` 或等待依赖任务 |
| 运行环境来源不可达 | “游戏运行环境准备失败：无法连接来源” | 检查网络后重试或改选预置来源 | Task `failed`；当前运行时 `RuntimeUnavailable` |
| 运行环境包损坏 | “游戏运行环境准备失败：获取的文件无法验证” | 清理不完整内容后重新获取 | Task `failed`（下载/内容验证失败）；当前运行时不变 |
| 运行环境磁盘不足 | “游戏运行环境准备失败：可用空间不足” | 释放空间后重试 | Task `failed`（按下载或安装阶段分类）；当前运行时不变 |
| 进程启动 API 报错 | “游戏进程未能启动” | 查看详细原因并重试 | Game `LaunchFailed` |
| 进程启动超时 | “等待游戏启动超时，正在确认并清理残留” | 等待清理确认 | Game `LaunchFailed`；未确认时禁立即重试 |
| 超时后发现残留进程 | “启动未完成，仍有残留进程需要处理” | 结束残留并重新确认 | task `failed`；清理未确认前不可取消为成功 |
| 进程确认后异常退出 | “游戏进程异常退出，游戏未保持运行” | 查看退出事实、重试或应用方案 | Game `LaunchFailed` |
| 进程确认前用户取消 | “启动已取消，未确认游戏运行” | 重新提交 | `cancelled`，前提是清理已确认 |
| 进程确认后用户取消 | “正在结束启动中的游戏并确认清理” | 等待结束 | 清理确认后 `cancelled`，否则 `failed` |
| 进程正常退出 | “游戏已退出” | 无需恢复 | Game 回到 `Installed` |
| MiPlay 关闭后进程仍在运行 | “检测到游戏仍在运行，正在同步状态” | 等待扫描完成 | 进程存在为 `Running`，否则按下次检测结果处理 |

## P0 沙盒授权、路径与权限

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 用户取消文件选择 | “未选择游戏路径” | 重新选择 | task `cancelled`，原状态不变 |
| 权限拒绝（用户或系统拒绝路径访问） | “无法访问所选游戏路径，请重新选择并允许访问” | 重新选择并授权 | task `failed`，不标记已安装 |
| 已保存的路径授权失效 | “所选路径的访问权限已失效” | 重新选择相同路径并重新授权 | task `failed`，原路径不当作可读 |
| 方案执行前权限能力不足 | “此兼容方案当前不可应用：需要的系统权限未获得” | 授权后重新检查 | `Unavailable`，不进入 `Applying` |
| 方案执行中权限被撤销 | “兼容方案应用被权限中断，正在恢复应用前状态” | 等待自动回滚；必要时重新授权 | `Failed`，回滚确认后 `RolledBack` |
| 回滚时权限再次被拒绝 | “恢复未完成，系统状态暂时无法确认” | 重新授权后执行恢复 | `Failed + 恢复未确认`，禁止同类重试 |
| 路径可访问但目标不是受支持游戏 | “无法识别所选文件对应的受支持游戏” | 重新选择正确可执行文件 | task `failed` |
| 重新选择路径中途取消 | “路径未更新” | 保留旧路径，之后重试 | 原业务状态不变 |

## P0 兼容方案应用与回滚

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 静态方案存在但不在发布清单 | “此方案当前版本不可用” | 无应用动作 | `Unavailable` |
| 方案适用游戏不匹配 | “此方案不适用于当前游戏” | 选择适用方案 | `Unavailable` |
| 方案资源缺失 | “此方案缺少可验证资源，无法应用” | 等待支持版本；不得继续 | `Unavailable` |
| 原始状态备份失败 | “无法保存应用前状态，方案未开始应用” | 修复权限/空间后重试 | task `failed`；无方案副作用 |
| 备份成功但修改尚未执行 | “原始状态已保存，正在应用；尚未生效” | 等待 | `Applying` |
| 修改命令返回成功但读回失败 | “方案修改未通过验证，正在自动恢复” | 等待回滚 | task `failed` + `RolledBack` 或恢复未确认 |
| 后置验证发现目标未生效 | “方案未验证通过，正在恢复应用前状态” | 等待回滚 | task `failed` + `RolledBack` |
| 回滚读回一致 | “方案应用未成功，已恢复应用前状态” | 稍后重试或换方案 | `RolledBack` |
| 回滚文件被删除/损坏 | “应用未成功，恢复所需的原始状态不可用” | 不再次应用；查看日志/重新授权 | `Failed + 恢复未确认` |
| 应用记录保存失败但目标验证通过 | “方案状态记录未保存，应用结果无法确认” | 不重复修改；先恢复或重新读取记录 | `Failed`；不得标记 `Applied` |
| 用户在应用前取消 | “兼容方案应用已取消，未改变目标” | 重新提交 | task `cancelled` |
| 用户在修改后取消 | “正在恢复应用前状态，恢复完成前不能结束” | 等待不可中断回滚 | `cancelled + RolledBack` 或 `failed` |
| 已应用方案再次应用 | “该方案已有一次已验证应用记录” | 先查看或回滚已有记录 | 不创建重复成功记录 |

## P0 完整性校验

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| manifest 非空且版本对应，全部通过 | “完整性校验通过，已确认文件与当前版本匹配” | 继续启动 | `IntegrityPassed` |
| 任一必需文件缺失 | “完整性校验未通过：缺少{文件}” | 官方修复/更新后重试 | `IntegrityFailed` |
| 任一文件哈希不匹配 | “完整性校验未通过：文件内容与清单不匹配” | 官方修复/更新后重试 | `IntegrityFailed` |
| manifest 缺失 | “无法确认完整性：找不到当前版本校验清单” | 稍后重试/使用受支持版本 | `IntegrityUnsupported` |
| manifest 为空 | “无法确认完整性：当前版本没有有效校验条目” | 稍后重试/使用受支持版本 | `IntegrityUnsupported` |
| manifest 版本不对应 | “无法确认完整性：校验清单与当前游戏版本不匹配” | 重新检测版本或使用受支持版本 | `IntegrityUnsupported` |
| 读取文件 I/O 失败 | “无法读取游戏文件，完整性校验未完成” | 重新授权/重新选择路径 | task `failed` |
| 校验中取消 | “完整性校验已取消，尚未得到新结论” | 手动重试 | task `cancelled` |

## P1 版本检测与重试

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 官方 API 超时 | “版本检测失败：官方版本暂时不可用” | 稍后重试 | task `failed`，游戏状态不变 |
| 网络断开 | “版本检测失败：当前没有网络连接” | 恢复网络后重试 | task `failed` |
| 官方返回不可解析数据 | “版本检测失败：未获得有效版本信息” | 稍后重试；保留日志 | task `failed` |
| 本地版本文件缺失 | “无法读取本地版本，暂时无法判断是否需要更新” | 重新选择路径/修复文件后重试 | task `failed` |
| 本地版本格式损坏 | “本地版本信息无法解析，暂时无法判断是否需要更新” | 修复文件或重新定位后重试 | task `failed` |
| 自动重试仍失败 | “仍未获得可信版本结果，自动重试已结束” | 手动重试或稍后处理 | task `failed`，不报告最新 |
| 失败前已有新版本结果 | “上次已确认有新版本，但本次检测失败” | 按上次提示处理或重试 | 保留 `UpdateAvailable`，标记过期 |
| 检测成功为最新 | “已确认当前为最新版本” | 继续启动 | task `completed` |
| 检测成功发现更新 | “已确认有新版本可用，MiPlay 不执行完整更新” | 使用官方更新流程 | task `completed` |

## P0/P1 TaskScheduler

| 边界 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 同一目标已有互斥任务 | “已有任务正在处理此目标，本次请求尚未执行” | 等待、取消新请求或查看现有任务 | 新任务保持 `pending` 或被拒绝 |
| 低优先级任务阻塞启动 | “启动请求已提交，正在等待前序任务” | 等待或取消等待任务 | `pending` |
| pending 任务取消 | “已取消，任务尚未执行” | 重新提交 | `cancelled` |
| running 任务取消且无副作用 | “已取消，未改变目标” | 重新提交 | `cancelled` |
| running 任务取消且需回滚 | “正在恢复应用前状态” | 等待回滚验证 | `cancelled + RolledBack` |
| SolutionRevert 已开始 | “恢复已开始，必须完成恢复验证” | 等待恢复完成，不接受取消 | `completed` 或 `failed`，不使用 `cancelled` |
| 任务执行失败但清理成功 | “任务未完成，已清理本次临时资源” | 按原因重试 | `failed` |
| 任务执行失败且清理失败 | “任务未完成，清理状态无法确认” | 先完成人工可执行的恢复路径 | `failed`，阻止同类立即重试 |
| 任务状态更新丢失 | “操作结果暂时无法确认，请勿重复执行” | 重新读取任务/历史记录 | 保持未确认，不伪造 `completed` |
| 任务完成事件先于业务验证到达 | “正在验证最终结果” | 等待后置验证 | 仍为 `running`，不能先显示成功 |

| 用户确认重新开始 | “将清除不可恢复的本地配置和历史，游戏文件不会因此被删除” | 重新定位路径并配置 | `freshStartConfirmed` |
| 恢复过程中应用退出 | “下次启动将继续要求恢复，未验证的数据不会被使用” | 重新启动并重试 | 不可用，原文件和备份保留 |

## 其他边界

1. **离线启动**：已完整校验且运行环境已就绪的游戏可以启动；版本检测失败不应阻止已满足本地前置条件的启动。网络相关任务单独显示 `failed`。
2. **游戏版本极旧**：没有适用兼容方案时显示“当前版本不在已知支持范围”，终态为方案 `Unavailable` 或完整性 `IntegrityUnsupported`，不得推荐不存在的方案。
3. **多款游戏同时操作**：每个游戏保留独立的业务结果；互斥任务排队时只显示等待事实，不把其他游戏完成误投影到当前游戏。
4. **兼容方案影响多个游戏**：应用前说明影响范围；回滚验证必须覆盖该方案声明的全部受影响系统资源，不能只验证当前游戏入口。
5. **重复点击同一操作**：已有相同目标的 `pending/running` 任务时，不创建第二个成功意图；反馈现有任务状态。
6. **语言切换期间失败**：失败记录的结构化事实不变，用户可见文案随当前语言一致切换；不能出现半句旧语言导致动作含义改变。
7. **日志导出**：日志只能帮助排障，不能代替后置验证、完整性结果或回滚确认；“日志已导出”不是业务成功。
8. **Deferred 功能边界**：官方游戏安装、完整游戏更新执行、自定义启动参数、帧率解锁和新增兼容方案不产生当前版本的可完成任务，也不应出现在本状态流的成功/失败矩阵中。

## P0 运行环境来源与版本检测（P1-UV-001 / P1-UV-002）

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 设置打开，版本目录尚未查询 | “正在检查游戏运行环境版本” | 等待或取消查询 | `catalogLoading`，不能显示空列表 |
| 批准来源返回匹配版本 | “找到可用的托管运行环境版本” | 选择后下载 | 目录结果，不是 `WineReady` |
| 来源有效但无匹配版本 | “没有可用的托管运行环境版本” | 稍后重试或等待 MiPlay 支持版本 | `noAvailableManagedVersion` |
| 当前选定来源不可达 | “无法连接所选运行环境版本源” | 恢复网络后重试或主动改选其他预置来源 | `networkFailure` |
| 当前选定来源返回 403 | “所选运行环境版本源拒绝访问（403）” | 稍后重试或改选其他预置来源；不提供 token | `sourceConfigurationError`，不是空列表 |
| allowlist/URL/镜像配置无效 | “运行环境版本源配置错误” | 更新 MiPlay 或等待修复，不要求用户改源 | `sourceConfigurationError` |
| 版本源响应格式/身份无法验证 | “版本源返回的信息无法验证” | 稍后重试并保留诊断 | `catalogInvalid` |
| 目标托管版本正在下载 | “正在下载{版本}，尚未安装完成” | 等待或按任务规则取消 | WineVersionDownload `running` |
| 下载完成但安装记录未提交 | “版本文件已取得，但安装尚未确认” | 重试提交或清理后重新下载 | task `failed` 或 `recoveryRequired` |
| 用户改选预置镜像 | “已选择{镜像}作为 Wine 版本源” | 查询所选来源；失败时按镜像错误重试或改选其他预置来源 | 保留来源选择事实，不自动回退 |
| 用户主动改选来源后查询成功 | “找到可用的托管运行环境版本” | 继续选择/下载 | 新查询保留选定来源身份，不是静默回退 |

镜像不能由用户输入或导入，不能因为镜像返回条目就绕过 allowlist、artifact 校验、安装提交或环境验证。

## P0/P1 本地版本和渠道来源（P1-UV-003）

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| `pkg_version` 有效且目标关联通过 | “已读取本地版本，正在验证对应关系” | 等待 manifest/远程比较 | 本地版本候选 |
| `pkg_version` 缺失/格式未知 | “无法读取本地版本，暂时无法判断” | 重新授权/定位或稍后重试 | VersionCheck `failed` |
| `config.ini` 仅提供渠道 | “已读取游戏渠道信息，仍需验证版本和文件” | 等待其他证据 | 渠道证据，不是完整性结果 |

| 本地来源与 manifest/远程版本冲突 | “版本信息互相冲突，暂时无法确认” | 重新定位、修复或使用受支持版本 | VersionCheck `failed` 或 `IntegrityUnsupported` |
| manifest 缺失/为空/版本不对应 | “无法确认完整性，当前没有可用校验清单” | 稍后重试或使用受支持版本 | `IntegrityUnsupported` |
| 仅有 `pkg_version`/`config.ini` 没有有效 manifest | “版本信息存在，但不能替代完整性校验” | 获取受支持 manifest 后重试 | 不得 `IntegrityPassed` |

## P1-REV-003 重启恢复

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| 持久 `Running`，活动进程存在 | “检测到游戏仍在运行，正在同步状态” | 等待扫描/确认 | `Running` |
| 持久 `Running`，无活动进程 | “上次游戏状态未完成同步，正在恢复” | 等待恢复提交 | `recoveryRequired`，暂不允许启动 |
| 退出状态提交失败 | “游戏退出状态未保存，暂时不能启动” | 重试恢复提交 | `failed + recoveryRequired` |
| AppData 与恢复记录同时不可写 | “游戏状态恢复未完成，暂时不能启动” | 保留保护并重试恢复 | `recoveryRequired`，不得静默 `Installed` |
| 恢复记录提交并重读成功 | “游戏状态已恢复” | 用户重新发起启动 | 新 UserIntent/Task，不能自动重启 |

## P1-REV-004 stale bookmark

| 场景 | 用户可见事实 | 恢复动作 | 终态 |
|------|-------------|---------|------|
| bookmark fresh | “游戏路径授权有效” | 继续当前消费者操作 | 可继续 |
| bookmark stale 正在刷新 | “正在刷新游戏路径授权” | 等待 | 不能发布消费者成功 |
| 刷新写回并重读成功 | “游戏路径授权已刷新并保存” | 继续校验/版本/启动 | 消费者可取得可信结果 |
| 刷新写回失败 | “路径授权已刷新但尚未保存，本次操作未完成” | 重试保存或重新选择路径 | `failed + recoveryRequired` |
| scope 启动失败/权限拒绝 | “无法访问所选游戏路径” | 重新授权或重新选择 | `failed` |
| 只剩 `lastKnownPath` | “已找到旧路径记录，但访问权限无法确认” | 重新选择路径 | 不得读写或发布成功 |

五个消费者必须得到同一事实：定位、完整性、版本检测、启动前校验和启动编排在刷新授权提交前都不能报告成功。

## P1-UV-006 Accessibility 边界

| 场景 | 必须被辅助技术读到 | 不得依赖 |
|------|------------------|---------|
| 游戏卡片 | 游戏名称、切换动作、选中状态、业务状态、当前可用动作 | 颜色、状态点、hover、背景 |
| 启动进度 | 目标游戏、任务状态、阶段、真实进度或“进度未知”、取消可用性 | 视觉进度条、动画速度、按钮大小 |
| 错误状态 | 目标、阶段、原因、是否产生副作用、终态、唯一恢复动作 | 红色、图标、透明度、弹出层位置 |
| `recoveryRequired` | “恢复未完成，当前不能重试”及恢复动作 | 仅禁用按钮或仅显示 spinner |
| 兼容方案 | `Unavailable`/`Applying`/`Applied`/`RolledBack`/`Failed` 和验证事实 | 备份图标、颜色或“完成”字样 |
| 版本目录 | 无可用版本、网络失败、配置错误、下载中 | 空列表、空状态图或加载动画推断 |
