# 关键界面状态描述（State Mapping）

> **文档状态**：活跃（Active）
> **UI 阶段**：界面结构设计
> **Task 4 修正**：交互控件语义与任务状态呈现
> **Task 4 修正**：主操作尺寸、Liquid Glass 融合和完整 Accessibility Tree
> **原则**：UI 不创造状态，只把业务状态、任务状态和结果事实分层呈现。

## 1. 状态呈现总则

UI 同时读取三类输入，不能用其中一类替代另一类：

| 输入 | UI 可表达的事实 | 不可推断的事实 |
|------|----------------|----------------|
| Task status | 请求是否等待、执行、完成、失败或取消 | 业务目标是否已经达成 |
| Task phase/progress | 当前阶段，以及可估算时的进度 | 进程已经运行或修改已经生效 |
| Business state/result | 游戏状态、完整性结果、方案结果、权限和回滚验证事实 | 未提供的成功、恢复或权限结论 |

- `pending` 显示“已提交，等待执行”，不得显示已启动、已应用或已完成。
- `running` 必须显示当前阶段；有可信数值时显示确定进度，没有数值时使用不定进度指示，不伪造百分比。
- `completed` 只表示该任务达到自身门槛或取得可信校验结果；必须同时显示 `outcome`。完整性任务的 `IntegrityFailed` 和 `IntegrityUnsupported` 可以是可信结果，但不是正向成功。
- `failed` 显示“目标未完成：原因”，保留失败阶段和唯一恢复动作；不得把目标提升为就绪、运行中或已应用。
- `cancelled` 只在清理或回滚已确认后显示“已取消，清理已确认”。回滚任务开始后不可取消。
- “命令返回”“备份成功”“进程已创建”“任务完成”不单独触发成功提示。

## 2. GameSelectionRailView

游戏图标的视觉内容仍由 `GameIconContent` 提供，但每个内容必须由标准 `Button` 包裹。`onTapGesture` 不得作为游戏切换或设置入口的动作来源。

| Game business state | 状态标识 | 可见事实 | Button 动作 |
|---------------------|---------|---------|------------|
| `PathUnset` / 无路径记录 | 中性未接入标识 | 游戏名称；尚未确认路径 | 选择该游戏上下文；随后由主操作提供定位入口 |
| `NotInstalled` | 中性未就绪标识 | 游戏名称；未确认可启动文件 | 选择该游戏上下文 |
| `Installed` | 就绪标识 | 游戏名称；已满足当前已知启动前提 | 选择该游戏上下文 |
| `UpdateAvailable` | 有更新标识 | 游戏名称；已确认存在更新提示 | 选择该游戏上下文 |
| `GameUpdating` | 进行中标识 | 游戏名称；更新正在执行 | 选择该游戏上下文；不能启动第二个更新 |
| `Launching` | 进行中标识 | 游戏名称；启动正在执行 | 选择该游戏上下文；主操作区呈不可操作 |
| `Running` | 运行中标识 | 游戏名称；游戏已确认运行 | 选择该游戏上下文 |
| `LaunchFailed` | 失败标识 | 游戏名称；上次启动未确认成功 | 选择该游戏上下文；主操作区提供查看修复入口 |

补充约束：

- 选中态和业务态是两件事；选中图标不得被误读为游戏已就绪。
- 状态点只作概览，失败阶段、进度、权限和回滚事实放在主操作区或详情窗口。
- 图标 Button 的可点击区域固定为图标内容的稳定尺寸，视觉层的 `.glassEffect`、圆角和 hover 不得改变布局尺寸。
- 每个 Button 均可通过鼠标、VoiceOver 和键盘焦点触发；按 Space 或 Return 执行同一“选择游戏”动作。

## 3. PrimaryActionButton

主窗口保持现有结构：右下角只有一个主操作按钮，没有额外的中心状态面板。按钮文案表达“下一步动作”，不是任务结果。

| Game / task state | 按钮呈现 | 用户可执行动作 |
|------------------|---------|---------------|
| `PathUnset` / `NotInstalled` | `定位游戏`（`Locate Game`） | 打开系统文件选择器；取消选择后原状态不变 |
| `Installed` | `启动`（`Launch`） | 提交启动任务 |
| `UpdateAvailable` | `更新`（`Update`） | 提交更新任务；不显示“更新成功”预设状态 |
| `LaunchFailed` | `查看修复方案`（`View Fixes`） | 打开游戏详情和兼容方案入口 |
| `GameUpdating` | 禁用，显示 `更新中…`（`Updating…`） | 无；等待任务结果 |
| `Launching` | 禁用，显示 `启动中…`（`Launching…`） | 无；等待进程确认或清理结果 |
| `Running` | 禁用，显示 `运行中`（`Running`） | 无；正常退出后再根据新业务状态更新 |
| 启动/更新/校验/Wine 任务 `pending` 或 `running` | 禁用或由任务反馈视图承载取消 | 显示任务阶段和进度；仅可取消的任务显示取消入口 |
| 可重试的 `failed` | `重试`（`Retry`）或原因对应的恢复动作 | 仅提交新的任务；不得把重试按钮当成成功状态 |

`WineReady` 是启动依赖的结果，不是游戏运行结果；运行环境准备完成后，仍需等待游戏进程确认才可呈现 `Running`。

## 4. 通用任务反馈映射

任务反馈附着于主操作区、详情窗口或对应 Sheet，不新增中心信息区，也不创建业务层不存在的状态。

| Task state | UI 内容 | 操作 |
|------------|---------|------|
| `pending` | 阶段“等待执行”；无确定进度 | 可取消任务显示 `取消`（`Cancel`） |
| `running` + 有进度 | 阶段名称 + 确定进度 + 已完成事实 | 可取消任务显示 `取消` |
| `running` + 无可估算进度 | 阶段名称 + 不定进度指示 | 可取消任务显示 `取消` |
| `failed` | 目标、失败阶段、事实、当前终态和唯一恢复动作 | 条件满足时显示 `重试`；否则显示重新授权、重新选择或查看日志 |
| `cancelled` | “已取消，清理已确认” + 原业务状态保持说明 | 重新提交新任务 |
| `completed` | 具体 outcome，例如“已确认游戏正在运行”或“已确认文件存在缺失” | 按 outcome 进入下一步；不显示通用“成功” |

### 启动任务

| Phase / result | 可见文案 | 允许的下一步 |
|---------------|---------|-------------|
| 排队 | `已提交，等待执行` / `Queued` | 取消或等待 |
| 启动前检查 | `正在检查游戏文件和权限` / `Checking game files and access` | 等待；可取消时显示取消 |
| 环境准备 | `正在准备游戏运行环境` / `Preparing game environment` | 等待；失败后按原因重试 |
| 进程启动 | `正在启动游戏进程` / `Starting game process` | 等待 |
| 进程确认 | `正在确认游戏运行` / `Confirming game is running` | 等待；没有确认前不得显示 `Running` |
| 用户取消且清理确认 | `启动已取消，清理已确认` / `Launch cancelled; cleanup confirmed` | 重新启动 |
| 前置失败 | `启动前检查未通过` / `Pre-launch check failed` | 修复列出的文件、权限或环境条件后重试 |
| 启动失败或超时 | `游戏未能启动` / `Game did not start` | 查看阶段和事实后重试；未确认残留清理前禁止立即重试 |
| 异常退出 | `游戏进程异常退出` / `Game process exited unexpectedly` | 查看退出事实、修复方案或重试 |
| 可信完成 | `已确认游戏正在运行` / `Game confirmed running` | 游戏进入 `Running`；不显示“启动成功” |

### 取消与重试

- `pending` 或尚未产生目标副作用时取消：显示 `cancelled`，保留原业务状态。
- 已发出启动请求、已发生修改或下载已有副作用时：按钮进入“正在清理/正在恢复”，清理和验证期间不可再次提交。
- 清理/回滚确认后才显示 `cancelled`；确认失败显示 `failed`，并说明状态暂时无法确认。
- 重试只创建新的用户意图/任务，不覆盖上一条失败事实；自动重试结束后提供一次明确的手动重试入口。

## 5. GameDetailWindow / 兼容方案状态映射

| Solution state / result | UI 呈现 | 用户动作 |
|-------------------------|---------|---------|
| `Unavailable` | 不可应用行，显示资源、适用范围或权限原因 | 重新授权、等待支持版本或选择其他方案 |
| `Applying` | 阶段列表：保存原始状态、执行修改、后置验证；按可信度显示进度 | 等待；修改开始后取消转入恢复流程 |
| `Applied` | “兼容方案已应用并验证通过”；同时明确“游戏尚未启动” | 关闭详情或单独重新启动 |
| `RolledBack` | “方案未应用，应用前状态已恢复并确认” | 稍后重试或选择其他方案 |
| `Failed` + 恢复未确认 | “方案未应用，系统状态暂时无法确认” | 重新授权、完成恢复或导出日志；禁止再次应用同一方案 |

`Applied` 只代表方案修改、后置验证、记录保存和可恢复快照均已确认，不代表游戏已经启动。备份成功只呈现“原始状态已保存，正在应用”，不能提前显示 `Applied`。

方案任务的过程文案：

- 执行前权限不足：`此兼容方案当前不可应用：需要的系统权限未获得` / `This fix is unavailable: required permission is missing`。
- 执行中权限失效：`权限中断，正在恢复应用前状态` / `Access was interrupted; restoring the previous state`。
- 修改或验证失败：`方案未验证通过，正在自动恢复` / `Fix was not verified; restoring the previous state`。
- 回滚任务开始后不显示取消按钮；回滚完成前不显示任何已恢复终态。

## 6. 完整性、权限和环境结果

| 结果事实 | UI 内容 | 不可呈现为 |
|---------|---------|-----------|
| `IntegrityPassed` | `完整性校验通过，已确认文件与当前版本匹配` | 已启动、已更新 |
| `IntegrityFailed` | `完整性校验未通过：发现缺失或损坏文件` + 文件事实 | 已就绪 |
| `IntegrityUnsupported` | `无法确认完整性：当前版本没有可用校验清单` | 完整、已就绪 |
| 权限失败 | `无法访问所选游戏路径，请重新选择并允许访问` | 文件损坏、已接入 |
| 方案执行前权限不足 | `此兼容方案当前不可应用：需要的系统权限未获得` | `Applying`、`Applied` |
| 运行环境获取中 | `正在准备游戏运行环境` + 阶段进度 | 环境已准备好 |
| 运行环境获取失败 | 具体的网络、来源、空间或文件验证原因 | 游戏已启动 |

## 7. Settings 与加载层

| 区域状态 | UI 呈现 | 交互 |
|---------|---------|------|
| Settings 可用 | NavigationSplitView + Form；配置值和只读事实分开 | 表单控件使用系统控件；齿轮 Button 打开独立 Settings 窗口 |
| 设置数据未确认 | 显示“设置尚未恢复/无法确认”，不以默认值冒充用户设置 | 重试读取或进入恢复流程 |
| 背景素材加载中 | 现有不透明加载层阻断底层交互 | 无；等待加载结果 |
| 背景素材加载失败 | 默认背景 + 可用的游戏选择和主操作 | 不把素材失败呈现为游戏启动失败 |

设置齿轮的标准控件语义、VoiceOver、键盘和 hover 要求见 `ui-interaction-implementation.md`。加载层只阻断被覆盖的控件，不改变业务状态。

## 8. Task 4 可访问状态映射

| UI 状态 | 可访问 label/value | 可访问 action |
|---------|--------------------|---------------|
| 游戏未选中 | `切换到{游戏名}`；`未选中，{业务状态}` | Space/Return 选择游戏 |
| 游戏已选中 | `切换到{游戏名}`；`已选中，{业务状态}` | Space/Return 选择游戏；不把选中读作已就绪 |
| 启动任务 `pending` | `启动任务`；`已提交，等待执行` | 可取消时提供 `取消启动` |
| 启动任务 `running` | `启动任务：{阶段}`；真实百分比或“进行中” | 可取消时提供 `取消启动` |
| 启动任务 `failed` | `启动失败`；失败阶段、事实和终态 | 提供唯一有效的 `重试启动`、重新授权或查看详情 |
| 启动任务 `cancelled` | `启动已取消`；`清理已确认` | 重新提交启动 |
| 启动任务 `completed` | `启动任务`；具体 outcome，例如“已确认游戏正在运行” | 按 outcome 继续；不读作通用成功 |
| 访问权限失败 | `无法访问所选游戏路径`；`需要重新授权或重新选择` | `重新授权` / `重新选择` |
| 兼容方案 `Unavailable` | `兼容方案不可用`；资源/权限/适用范围原因 | `查看原因` 或选择其他方案 |
| 兼容方案回滚中 | `正在恢复应用前状态`；阶段和验证状态 | 不提供取消 |
| `RolledBack` | `方案未应用`；`应用前状态已恢复并确认` | 稍后重试或选择其他方案 |

`BackgroundView`、视频、图片、状态圆点、玻璃材质和装饰性 focus 背景均不单独进入 VoiceOver 顺序。详细节点、label/value/hint 和键盘顺序见 `ui-validation-and-accessibility.md`。

## 10. 重启恢复与旧路径授权刷新  
(涵盖 P1-REV-003 重启恢复 / P1-REV-004 stale bookmark / 路径授权刷新)

| 恢复事实 | UI 呈现 | 交互 |
|---------|---------|------|
| `persistedRunningNoProcess` | “上次游戏状态未完成同步，正在恢复” + 恢复进度指示 | 无；等待恢复提交 |
| `recoveryCommitPending` | “正在保存游戏退出状态” + 进度指示 | 无；等待确认 |
| `recoveryCommitted` | “游戏状态已恢复” | 允许新启动 |
| `recoveryPersistenceFailed` | “游戏状态恢复未完成，暂时不能启动” | 重试恢复或导出日志 |
| `locationFresh` | 绿色对勾标识或无额外提示 | 继续当前操作 |
| `locationStaleRefreshing` | “正在刷新游戏路径授权” + 进度指示 | 等待 |
| `locationRefreshCommitted` | “游戏路径授权已刷新并保存” | 继续发布结果 |
| `locationRefreshPersistenceFailed` | “路径授权已刷新但尚未保存，本次操作未完成” | 重试保存或重新选择路径 |

**关键约束**：恢复期间主操作区显示恢复事实，不显示常规状态文字；恢复确认后才允许新启动任务。

## 11. Task 4 几何约束

- `GameIconButton` 命中框固定 `64 × 64pt`，玻璃面板固定 `56 × 56pt`，游戏 Button 间距为 `12pt`。
- hover 最大 `1.04`、选中最大 `1.08` 只作用于 glyph；玻璃面板和 Button 命中框不缩放。
- `PrimaryActionButton` 最小尺寸为 `220 × 64pt`；disabled 的静态 `Running` 不显示伪进度动画。

## 2026-10-08 视觉状态补充

- 游戏图标的彩色描边表达业务状态；左侧白色短条独立表达选中状态，并为 Button 添加 `.isSelected` 辅助技术 trait。颜色不再是选择的唯一线索。
- 主按钮按已有 `PrimaryAction` 显示定位、播放、更新符号；不从文案生成新操作。禁用与启动中的业务判断保持原样。
- `MainTaskFeedbackView` 仅呈现真实 `LaunchProgress` 与 `RecoveryRecord`；百分比不生成、不插值。恢复记录已解决后隐藏。
- 无任务、无未解决恢复记录时不生成反馈面板；减少透明度时反馈面板使用不透明深色底。

## 2026-10-09 原生状态补充

主窗口恢复提示仅取当前 selectedGameId 对应、resolvedAt 为 nil 的记录。准备遮罩优先展示 failure；Wine 和媒体阶段均使用对应失败标题。白色背景局部固定 light scheme，系统 Dark Mode 下文字仍按浅色语义渲染。正常玻璃保留 clear 黑 tint；Increase Contrast 或 Reduce Transparency 使用不透明深色 fallback。Disabled 主按钮仅降低文字强度，保留可读文案，不整体淡出面板。
