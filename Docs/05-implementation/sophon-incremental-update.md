# Sophon 分批更新与中断续装

已定位游戏的正式更新使用 v2 事务，按文件生成、校验、提交并记录进度。完成的文件保留在新版状态，中断后向前续装，不再将整次更新回滚到旧版本。此策略减少同时保留全部新版文件造成的临时磁盘占用。

## 安装与空间释放

1. 读取官方正式清单和已安装语音包，校验本地资源，创建固定目标版本的更新计划。
2. 根据差分的旧源依赖安排文件顺序。通常先处理需要某个旧文件的目标，再替换该旧文件；依赖成环时保留仍被后续文件引用的旧源。
3. 为当前文件复用已校验的预下载缓存，应用 HDIFF13、复制差分对象中的完整目标内容，或回退到完整资源下载。新版文件先进入事务的 `staged` 目录并校验大小和官方 MD5。
4. 持久化当前文件的提交意图，再移动旧文件、安装新文件并持久化完成进度。两次移动之间不响应取消；下一文件开始前响应暂停。
5. 及时释放不再被未完成差分引用的旧源和已无后续用途的缓存。保留必要旧源直至最后一个使用者完成。

临时空间主要由当前目标文件、当前补丁切片、尚未使用的下载缓存、仍需引用的旧源组成，另需考虑游戏最终容量增长。它不再固定等于全部变更文件的大小总和，但也不能承诺只占预下载包大小。每批写入检查可用空间，并保留至少 2 GiB 余量；空间不足时保留已安装进度，腾出空间后继续。

## 暂停与继续

安装、更新任务提供“暂停”和“继续安装／继续更新”。任务历史沿用 `cancelled` 状态表示用户暂停，不要求迁移历史枚举。已完成的更新文件和未消费缓存保留；当前未提交文件可以重新生成。

部分更新期间游戏维持 `gameUpdating` 状态，事务目录也会阻止启动。主按钮提供“继续更新”，不能把仅有可执行文件视为完整安装。恢复会先校验已完成文件，再归并当前文件的移动边界，随后从未完成部分继续。若发现文件被外部修改或官方目标清单变化，保留续装目录并报告错误，避免静默混用不同版本。

暂停后应保留 `.miplay-sophon-transaction` 和 `.miplay-sophon-download`，使用 MiPlay 的继续入口完成更新。删除事务记录会丢失安装计划及仍需使用的旧源关系。

## 完成与兼容

所有目标资源通过完整校验后，最后提交 `config.ini` 中的新版本。完成的 v2 日志继续作为收据保留；调度器持久化游戏版本和已安装状态后，才调用 `finalizeCommittedUpdate` 清理事务。若在登记或清理之间退出，下次先核对完成事实再补齐登记，不重复回滚已安装文件。

旧 v1 事务仍使用原来的回滚恢复，清理旧事务后才能开始新更新。全新安装保留原有 v1 事务：目标目录没有一套旧游戏需要备份，完整资源缓存优先硬链接到暂存目录，不会仅因暂存再复制一整套新游戏。

## 验证范围

隔离测试需要覆盖暂停后续装、各移动边界的崩溃恢复、旧源依赖与循环、损坏或外部修改检测、空间不足、清单变化、最终配置和收据清理，以及旧 v1 恢复兼容。

此前原神国服 7.1.0→7.2.0 和官方清单 2,974 文件校验通过，验证的是改造前的正式更新流程。该结果不能替代 v2 分批更新的实机验收。新版流程的实际峰值空间、安装耗时及网络复用量，需要在独立的旧版本副本或下次正式更新中测量；不能对已经更新完成的游戏重跑一次当前版本检查，就认定完成了真实差分更新验收。
