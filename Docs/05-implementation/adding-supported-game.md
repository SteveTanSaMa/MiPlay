# 增加内置游戏

MiPlay 使用由开发者维护的固定游戏列表，不从外部配置或用户输入动态注册游戏。增加游戏需要先核对其官方国服接口、资源格式以及实际运行环境；下载可用不代表游戏能够启动。

1. 在 `GameType` 增加稳定的持久化标识，并在 `GameType.definition` 明确填写名称、官方身份、国服程序、目录候选、素材标识及磁盘估算。显式声明支持哪些内容操作，未验证的操作不要开启。已有标识不能改名。
2. 不修改 `GameRegistry.legacyBuiltInGameTypes`。它是引入游戏目录记录之前的固定三游戏基线，用于跨版本迁移；注册库会只追加用户尚未见过的新类型，并保留已移除游戏及原有授权。使用迁移测试验证旧数据、空库、重复启动及 ID 冲突。
3. 若支持 Sophon，在 `SophonGameProfile` 中声明语音包探测路径，并对照实际 API 核验国服身份、版本、资源分类、清单、语音包、压缩和差分格式。按安装、更新、预下载分别测试，包含断点、校验、提交、回滚和缓存复用。不能假定新游戏与现有三款采用完全相同的格式。
4. 在 `LaunchCompatibilityEnvironment.profile(for:)` 和相关启动准备、注册表、Vulkan 路径、环境变量中明确选择并验证该游戏的兼容行为。不要仅因它使用同一发行商或下载协议就套用其他游戏的兼容方案；需要独立验证 Wine、图形、权限及游戏自身的运行要求。
5. 检查性能选项、兼容方案、游戏图标、背景及新闻的适用性。主页和设置页从内置列表生成入口，但不能因此假设每项资源或功能都已适配。未验证的游戏特定选项不应自动继承。
6. 使用隔离目录运行目录契约、注册库迁移、设置页、版本检查、下载更新和启动配置测试。涉及真实账号或游戏安装的验收必须明确核对目标目录，保留用户文件，并分别记录官方接口验证与实机结果。

实际正式更新需要在游戏版本发布后验证：预下载分支和正式分支的清单或对象身份可能变化，缓存并不保证一定复用。
