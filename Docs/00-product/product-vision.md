# MiPlay 产品愿景

> **文档状态**：已冻结（Freezed）
> **产品阶段**：Product Definition（问题空间定义）

---

## 1. 产品目标（Product Vision）

```
一句话描述：让普通 Mac 用户无需理解技术细节就能启动米哈游游戏。

补充说明（200 字以内）：
Mac 玩家在米哈游游戏中长期处于二等公民地位——官方启动器缺失、第三方工具要求
理解 Wine/转译/游戏引擎兼容性等技术概念。MiPlay 将 Wine 环境管理、兼容性配置
等技术复杂性封装在背后，提供一个符合 Apple 平台习惯的体验，使得"想玩游戏"
这个简单意图不需要变成"研究配置"的过程。Wine 只由 MiPlay 从官方 GitHub 或
预置可信镜像获取并托管，不检测或复用本机 Wine。我们不解决兼容性问题，我们让
已知兼容方案可被发现和使用。
```

## 2. 用户范围（User Segments）

### 主要用户类型 1：Mac 原生游戏玩家
- **典型背景**：长期使用 Mac，习惯 App Store 或 Steam 的即装即玩体验，对 Windows 游戏生态不熟悉，但对米哈游游戏内容（剧情、角色、活动）有持续兴趣。
- **核心诉求**：不想为了玩一个游戏去学习 Wine/转译/容器等概念，希望像打开其他 Mac 应用一样启动游戏。
- **使用场景**：下班回家躺在沙发上，打开 MacBook，想直接进入《原神》做每日委托，不想经历配置检查、终端命令或论坛搜索。

### 主要用户类型 2：多游戏玩家
- **典型背景**：同时玩两款以上米哈游游戏（如《原神》+《星穹铁道》），当前需要在不同启动器或不同文件夹之间切换。
- **核心诉求**：一个统一的入口来管理多款米哈游游戏的启动，知道哪些游戏有新版本需要更新，了解当前各游戏的运行状态。
- **使用场景**：周末想轮流体验不同游戏的新活动内容，希望一个应用就能看到所有游戏的启动入口和运行状态，而不需要在 Launchpad 或应用程序文件夹中分别寻找。

### 主要用户类型 3：兼容性敏感玩家
- **典型背景**：已尝试或听说过 Mac 上运行米哈游游戏的兼容性问题，有一定技术恐惧，担心系统更新或游戏版本更新后游戏无法运行。
- **核心诉求**：在游戏出现启动异常时，能快速应用已知的兼容方案解决问题，降低试错成本。
- **使用场景**：macOS 系统更新后，发现自己的《绝区零》无法启动了，希望有一个工具能直接应用已知方案来修复，而不是自己去论坛搜索教程。

## 3. 成功标准（Success Metrics）

1. **启动路径最短** — 一名已完成游戏安装的用户，从打开 MiPlay 到进入游戏画面的操作步骤，不超过打开一个系统原生应用所需的操作量。
2. **故障恢复可自助** — 当游戏因已知兼容性问题无法启动时，用户能在 MiPlay 内找到当前版本发布清单中且通过资源与权限检查的方案，无需切换到浏览器搜索解决方案；未发布或不可用的方案不得被伪装为可应用。
3. **状态可理解性** — 用户能够了解每款游戏的当前状态（未安装 / 已就绪 / 运行中 / 需更新 / 启动失败），并知晓原因。
4. **风险告知清晰** — 在使用任何兼容方案前，用户能明确知悉该方案的性质和潜在风险，并能自主选择是否继续。
5. **已安装游戏接入闭环** — 一名已完成游戏安装的用户，能通过 MiPlay 完成从定位游戏路径、使用非空且版本对应的 manifest 校验完整性到启动的过程。manifest 不支持时不得报告完整；官方游戏下载与安装引导属于 Deferred，不纳入当前版本成功门槛。
6. **Wine 技术零负担** — 一名首次使用 MiPlay 的用户，从 MiPlay 获取批准来源的托管 Wine 到启动游戏的全过程中，无需理解 Wine 的技术构成、手动配置来源或管理 prefix；用户仍可以查看当前运行时的安全名称、版本、来源和就绪状态。本机 Wine 不被检测、展示、导入或复用。
7. **设置事实不失真** — 用户能查看目标游戏 `config.ini` 的原始字段和值，并能确认设置按 Game ID 独立保存；MiPlay 不猜测 `channel`、`cps` 等字段的友好含义。
8. **背景选择不串游戏** — 用户能在目标游戏的有效版本背景组之间切换，切换不改变其他游戏；目标组不可用时保留上一有效组并报告原因。
9. **高级目标有明确状态** — Retina、Steam patch / Steam 白名单、旧版反作弊文件替换、Metal HUD、左 Command 映射 Control 和 hosts 屏蔽属于当前版本目标，但在本轮 Deferred 时不得被宣传或记录为已完成。
10. **失败可诊断** — 当核心流程失败、取消或需要恢复时，用户能够知道阶段、原因类别和下一步动作；诊断信息经过隐私清理，不泄露密码、Token、完整路径、游戏文件内容或个人数据。
