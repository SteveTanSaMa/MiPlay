# MiPlay 使用情境与核心问题

## 使用情境与核心问题拆解

### 使用情境 1：日常启动游戏
- **用户**：已完成游戏安装的 Mac 玩家。
- **触发场景**：想玩游戏时，打开 Mac 准备进入游戏。
- **目标**：用最少的操作步骤启动目标游戏。
- **当前痛点**：需要从多个位置寻找启动文件，或使用第三方工具时需先启动工具再启动游戏，操作路径冗长。
- **MiPlay 的解决方式（一句话）**：提供一个专注的入口，让用户定位游戏并发起启动，其余流程由工具接管。

### 使用情境 2：首次安装游戏（Deferred / 不纳入当前版本）
- **用户**：刚购买 Mac 或刚决定玩某款米哈游游戏的新玩家。
- **触发场景**：想玩某款米哈游游戏，但电脑上还没有安装该游戏的客户端。
- **目标**：获取并安装游戏客户端。
- **当前痛点**：需要自行找到米哈游官方下载页面，下载后还要确认安装路径和文件完整性。
- **当前版本边界**：该情境保留为未来产品目标，当前版本不负责从官方资源获取和安装客户端；用户需先完成游戏安装，再通过 MiPlay 定位游戏路径并继续校验和启动。

### 使用情境 3：游戏异常启动后修复
- **用户**：已正常游玩一段时间，但突然遇到启动问题的活跃玩家。
- **触发场景**：游戏版本更新后无法启动，或系统更新后游戏出现异常。
- **目标**：找到问题原因并让游戏恢复到可运行状态。
- **当前痛点**：问题原因复杂（可能是反作弊、系统配置、网络环境等），用户不知道从何排查，只能去论坛发帖求助。
- **MiPlay 的解决方式（一句话）**：提供当前版本发布清单中、已通过资源与权限检查的社区兼容方案；方案真实执行并验证成功后才视为已应用。

### 使用情境 4：了解多款游戏的整体状况
- **用户**：同时拥有多款米哈游游戏的多游戏玩家。
- **触发场景**：想了解所有游戏的当前状态（哪些在运行、哪些需要更新、哪些未安装）。
- **目标**：在一个地方总览所有米哈游游戏的状况。
- **当前痛点**：需要分别打开不同的启动工具或检查不同游戏的文件夹来了解各游戏状态，信息分散。
- **MiPlay 的解决方式（一句话）**：让用户能够了解三款米哈游游戏的基本状态。

### 使用情境 5：首次配置 Wine 运行时
- **用户**：首次使用 MiPlay 的新 Mac 用户，电脑上尚未安装任何 Wine 运行时。
- **触发场景**：刚下载 MiPlay，准备启动第一款米哈游游戏，但 Mac 缺少游戏运行所需的 Wine 环境。
- **目标**：让批准来源中的合适 Wine 版本自动就位，用户无需理解 Wine 的技术构成或手动配置来源。
- **当前痛点**：用户需要自行搜索社区推荐的 Wine 构建版本，理解不同分支（Wine/Game Porting Toolkit/Wine-Crossover）的差异，手动完成下载、安装和配置——对非技术用户是不可逾越的门槛。
- **MiPlay 的解决方式（一句话）**：在用户首次尝试启动游戏时从默认官方 GitHub 或用户选择的预置可信镜像获取所需的 Wine 版本，交由 MiPlay 托管并分别完成安装、选中和当前游戏 readiness 验证；系统 Wine、Whisky 或 CrossOver 不被检测、展示、导入或复用。

### 使用情境 6：判断当前运行时是否可用
- **用户**：希望直接启动游戏、但无法从“当前运行时”标题判断 Wine 是否真的可运行的 Mac 玩家。
- **触发场景**：下载完成、切换版本、启动失败或重新打开 MiPlay 后，用户需要确认当前游戏使用的运行时。
- **目标**：明确知道当前游戏选中的托管 Wine 名称、版本、批准来源、安装状态和 readiness，而不是猜测某个路径或本机 Wine 是否被使用。
- **当前痛点**：远程可用版本、已安装版本、当前选中版本和可启动状态容易被压成同一个标签；下载完成也可能找不到托管 executable 或 prefix 尚未就绪。
- **MiPlay 的解决方式（一句话）**：按当前 Game ID 分层表达版本身份、安装、选中和 readiness；未就绪、失败、取消或需要恢复时明确阻止启动和下一步动作，不回退到外部 Wine。

### 使用情境 7：感知当前游戏版本主题
- **用户**：活跃的米哈游游戏玩家，关注游戏版本更新内容。
- **触发场景**：打开 MiPlay 时想了解对应游戏当前版本的主题风格或视觉标识。
- **目标**：通过视觉方式直观感受到当前游戏版本的主题氛围。
- **当前痛点**：需要打开浏览器或游戏内才能了解当前版本的主题视觉，启动器本身与游戏版本内容割裂。
- **MiPlay 的解决方式（一句话）**：展示与游戏当前版本对应的官方视觉素材，让启动体验与游戏版本内容产生关联。

### 使用情境 8：查看配置并维护按游戏设置
- **用户**：需要排查启动问题、但不希望修改另一款游戏配置的多游戏玩家。
- **触发场景**：想查看某款游戏当前 `config.ini`，或调整仅对该游戏生效的设置。
- **目标**：看到真实配置字段和值，并确认设置只属于当前游戏。
- **当前痛点**：配置字段含义不稳定，工具可能把原始值误解释成版本或渠道；多游戏共用设置还可能造成串用。
- **MiPlay 的解决方式（一句话）**：展示 `config.ini` 原始 key/value，并按 Game ID 保存和读取游戏设置；不猜测 `channel`、`cps` 等字段含义。

### 使用情境 9：切换游戏版本背景组
- **用户**：同时管理多款米哈游游戏、关注版本主题的玩家。
- **触发场景**：想为当前游戏切换另一组有效的官方版本背景素材。
- **目标**：切换目标游戏的背景组，同时保持其他游戏选择不变。
- **当前痛点**：背景组可能因版本或资源不可用而加载失败，失败后不应清空已有选择或影响其他游戏。
- **MiPlay 的解决方式（一句话）**：按 Game ID 保存背景组选择；目标组不可用时保留上一有效组并保留失败事实。

### 使用情境 10：查看设置页设备信息
- **用户**：需要确认 MiPlay 运行环境基本信息的 Mac 玩家。
- **触发场景**：排查 Wine 下载/安装问题，或确认系统版本和存储空间是否可读。
- **目标**：看到系统报告中的 Mac 型号、macOS 版本和与 MiPlay 托管 Wine 目标相关的磁盘空间。
- **当前痛点**：型号可能被错误推断，磁盘空间可能来自无关卷或旧缓存；读取失败时用户无法判断信息是否准确。
- **MiPlay 的解决方式（一句话）**：设置页只展示准确的只读系统事实；字段读取失败显示不可用并保留失败事实，不把设备信息当作 Wine readiness 或启动门禁。

### 使用情境 11：诊断启动或环境失败
- **用户**：遇到 Wine、权限、游戏启动、完整性或兼容方案问题，需要向自己或社区说明情况的玩家。
- **触发场景**：下载超时、Wine 未就绪、路径授权失效、启动失败、任务取消、恢复未完成或背景/设置刷新异常。
- **目标**：知道失败发生在哪个阶段、为什么失败、当前是否有副作用，以及下一步应重试、重新授权、回滚还是等待恢复。
- **当前痛点**：只有“失败”或一段开发错误文本时，用户无法区分网络、权限、资源、进程和恢复问题，也无法安全地提供排障信息。
- **MiPlay 的解决方式（一句话）**：记录核心流程的非敏感诊断事实，并将可行动的原因摘要与用户可见错误分开；不记录密码、Token、完整用户路径、游戏文件内容或个人数据。
