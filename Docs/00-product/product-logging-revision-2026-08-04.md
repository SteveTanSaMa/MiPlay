# MiPlay 诊断日志产品需求修订 2026-08-04

> **文档状态**：已冻结（Freezed）
> **责任阶段**：Product / Review 后用户验证
> **适用范围**：当前版本诊断日志的目标、覆盖、可见性和隐私边界
> **实现边界**：本文定义记录什么和用户能看到什么，不定义 Swift API、日志协议或存储实现。

## 1. 产品目标

MiPlay 的诊断日志解决一个明确问题：当 Wine、权限、游戏路径、启动、完整性、兼容方案、设置或背景流程失败时，用户和排障人员能够判断：

1. 失败发生在哪个流程阶段。
2. 失败影响哪个游戏、任务或批准来源。
3. 失败原因属于网络、资源、权限、状态、进程、校验、取消还是恢复。
4. 是否已经产生副作用，清理或回滚是否完成。
5. 下一步是重试、重新授权、改选批准来源、等待恢复、查看设置，还是不能继续操作。

日志的目标是提供可追踪事实，不是把任何流程包装成成功。日志存在、任务完成、代码入口执行或错误文本输出，都不能单独证明 `WineReady`、启动成功、`Applied` 或 `IntegrityPassed`。

## 2. 三类信息的边界

| 信息类别 | 面向对象 | 当前版本要求 | 内容边界 |
|---|---|---|---|
| 用户可见错误 | 当前用户 | Must | 使用安全的原因类别、目标、当前阶段和下一步动作；不显示原始路径、Token、堆栈、完整 URL 或文件内容。 |
| 诊断日志 | 用户排障、Review、QA、开发排障 | Must | 记录核心流程的阶段、结果、失败原因和恢复上下文；经过隐私清理，可供本地查看或导出。 |
| 开发调试信息 | 开发人员 | Out of Scope（用户产品承诺） | 不作为当前版本用户可见能力、导出格式或成功标准；即使存在，也必须遵守同样的敏感信息禁止规则。 |

用户可见错误和诊断日志必须来自同一业务事实，但详细程度不同。用户界面可以显示“Wine 下载失败，建议重试或改选批准镜像”，诊断日志可以补充来源 ID、阶段、HTTP 状态类别和清理结果，但不得暴露签名 URL 或完整本机路径。

## 3. 诊断事件的产品语义

每个核心流程至少需要能够关联以下安全上下文；这是事件内容要求，不是具体数据结构要求：

| 上下文 | 规则 |
|---|---|
| 时间 | 能判断事件发生顺序；需要时能判断阶段耗时。 |
| 关联标识 | 使用流程、任务或一次用户意图的关联标识；不得使用密码、Token 或 bookmark 内容作为标识。 |
| 作用域 | 记录 Game ID、批准来源 ID、Wine 版本身份或背景组 ID 等安全业务身份；不记录完整本机路径。 |
| 操作和阶段 | 说明是在发现、读取、授权、下载、校验、解压、准备、启动、终止、清理、回滚还是刷新阶段。 |
| 结果 | 至少能区分开始、进行中、成功、失败、取消、不可用、未支持和恢复未完成。结果不得超越对应业务门槛。 |
| 原因 | 使用非敏感的稳定原因类别或安全摘要，例如网络超时、HTTP 拒绝、权限未授予、资源不完整、manifest 不支持、prefix 未准备。 |
| 副作用与恢复 | 失败后说明是否已经产生外部副作用、清理是否完成、回滚是否完成、是否仍有 `recoveryRequired` 保护。 |
| 规模和耗时 | 可记录下载字节数、条目数、退出码、信号、耗时或资源计数等排障所需摘要；不记录文件内容。 |

失败、取消、不可用、未支持和恢复未完成事件必须至少包含：操作、阶段、原因类别、关联上下文和恢复/下一步事实。没有这些信息的单一“失败”文本不满足产品日志要求。

## 4. 核心流程日志覆盖矩阵

“Must”表示该流程的关键状态和失败原因必须可追踪，不表示必须为每个内部函数产生一条日志，也不以日志条数作为完成标准。

| 流程 | Must 记录的诊断事实 | 用户可见边界 | 关联 Review / 用户验证 |
|---|---|---|---|
| App 启动和初始化 | 应用会话开始；持久化数据读取、迁移或恢复阶段；初始化结果；初始化失败原因和是否影响继续使用。 | 初始化失败显示受影响能力和恢复动作，不显示原始文件路径或堆栈。 | P2-05；用户验证中的启动/签名与 AppData 检查。 |
| 游戏添加、选择、删除 | Game ID、用户动作、路径授权请求结果、当前选择变化、删除结果和持久化结果。删除失败必须说明对象是否仍保留。 | 不显示完整用户路径、bookmark 原文或文件内容；不把选择动作显示为安装成功。 | P1-01、P1-02；真实 NSOpenPanel / 路径检查。 |
| bookmark resolve | resolve 开始/完成、是否 stale、刷新尝试、刷新写回结果、scope 获取/释放是否配对、权限失败原因。 | 用户看到路径授权状态和重新授权动作，不看到 bookmark 数据。 | P1-01、P1-02；stale、移动/改名、撤销权限验证。 |
| Wine 版本发现 | 选择的来源 ID、查询阶段、API/响应类别、allowlist 过滤、架构过滤、可用版本结果、空目录或 schema 无效原因。 | 显示来源类别、版本结果和安全的重试/改选动作；不显示完整 URL、Token 或响应正文。 | P1-04、P1-06；allowlist、403、429、空目录和超时验证。 |
| Wine 镜像选择 | 用户选择的批准镜像 ID、来源身份是否保持、目录结果是否仍属于该来源、改选或失败结果。 | 不提供自由 URL；不把官方失败改写成镜像成功，也不展示未批准来源。 | Product Wine-only / 镜像策略；真实 source 验证。 |
| Wine 下载 | 目标 Wine 版本身份、阶段、进度摘要、HTTP 状态类别、取消请求、传输失败、部分下载和最终结果。 | 用户看到失败阶段和重试/改选动作；不得暴露签名下载 URL 或完整临时路径。 | P1-05、P1-06、P2-02；asset 超时、取消和清理验证。 |
| Wine 校验、解压和安装 | 资源身份校验结果、架构结果、解压阶段、安装提交、持久化写回和重读结果。 | 目录存在、进度 100% 或版本名称出现不等于安装成功；错误需说明未进入可用集合。 | P1-02、P1-07；越界、symlink、cleanup 和提交失败验证。 |
| Wine prefix / `WineReady` | runtime 选择、prefix 准备开始/完成/失败、基础环境结果、版本身份一致性、readiness gate 结果。 | 未准备 prefix 不得显示完整 `WineReady`；错误说明需保留“不能启动”的原因。 | P1-04；真实 `wineboot -u` 和 prefix 验证。 |
| Wine 删除和清理 | 删除目标的安全身份、删除阶段、是否在托管范围内、清理结果、清理失败和 recovery 状态。 | 不显示完整路径；清理失败不能被显示为取消成功或安装失败已处理。 | P1-02、P1-07、P2-02；托管 root、越界和 cleanup failure。 |
| PreLaunch | 启动意图、前置校验阶段、路径/授权/完整性/Wine/prefix 检查结果、拒绝原因和是否发出进程启动。 | 前置失败显示可修复原因；不能显示“正在启动”掩盖未执行事实。 | P1-02、P1-04、P1-08；真实游戏启动前置检查。 |
| TaskScheduler | 任务目标、接受/排队/运行/完成/失败/取消/recoveryRequired 状态、资源冲突、取消传播和最终 outcome。 | 任务 `completed` 不自动等于业务成功；取消请求不自动等于取消完成。 | P1-05、P2-02、P2-03；Receipt、锁、取消和 Settings projection。 |
| LaunchOrchestrator | 启动编排阶段、runtime/prefix 选择、进程启动请求、健康确认、退出收敛、AppData 写回和恢复门禁。 | 不把进程创建、任务运行或日志出现当作游戏启动成功。 | P1-04、P1-08；真实 Wine/game、恢复和同目标门禁。 |
| Process 启动、终止、取消和退出 | 进程角色、启动结果、健康确认、终止请求、取消阶段、信号/退出码、等待确认和耗时。 | 不记录完整命令行、环境变量或路径；用户看到安全的进程阶段和动作。 | P1-08、P2-02；Process lifecycle 和 Wine 运行验证。 |
| `pkg_version` / `config.ini` | 读取开始/结果、字段解析状态、条目数量摘要、size/MD5 校验结果、manifest/channel mapping、冲突/空/损坏结果。 | UI 可按 Product 规则显示 `config.ini` 原始字段；日志不记录原始配置值或整个 JSON Lines。 | P1-03；真实渠道样本、冲突和不支持字段验证。 |
| 完整性校验 | manifest 身份、游戏/客户端版本对应结果、校验阶段、缺失/不匹配数量和最终 `IntegrityPassed` / `IntegrityFailed` / `IntegrityUnsupported`。 | 空、缺失、不支持或版本不对应 manifest 不能显示通过；不展示文件内容。 | P1-03；完整性与 manifest 用户验证。 |
| 兼容性方案 | 方案 ID、适用游戏、能力检查、资源/权限结果、执行阶段、后置验证、`.applied`、失败和回滚结果。 | `CS-01` 只有真实执行和验证后可显示 Applied；Deferred 方案不得出现可应用语义。 | Product 发布清单；helper/权限/读回/回滚验证。 |
| 性能选项 | 选项 ID、适用性、资源/权限检查、应用或取消、后置结果和恢复事实。 | A-01 至 A-06 Deferred 时不显示为已实现；日志不成为 Deferred 功能的伪实现。 | Product A-01 至 A-06；当前不进入 Implementation 验收。 |
| 背景下载、转码、取消和切换 | Game ID、背景组 ID、下载/转码/缓存阶段、取消、旧结果丢弃、切换结果和资源释放摘要。 | 目标组失败时保留上一有效组；不显示媒体文件完整路径或内容。 | P2-04；Performance 背景生命周期、取消和旧状态覆盖。 |
| Settings 状态刷新 | 刷新触发原因、目标 Game ID、Wine catalog/readiness/error outcome、设置读取/保存结果、背景组结果和最终投影。 | readiness error、not selected、not downloaded 不能压平为同一“就绪/失败”；不显示原始设置值。 | P2-03；Settings projection 和真实窗口验证。 |
| 日志写入、轮转和导出 | 诊断记录写入/flush/export 的结果、失败原因、导出是否完整以及安全清理结果。日志故障不能篡改业务结果。 | 不自动上传；导出内容必须经过同样的隐私清理；写入失败时提示“诊断记录可能不完整”。 | Performance 日志 flush/export；用户排障需求。 |

## 5. 用户可见错误规则

每个用户可见失败至少回答四件事：

1. **对象**：哪个游戏、Wine 版本、任务或背景组受影响。
2. **阶段**：发现、授权、下载、校验、准备、启动、运行、退出、清理、回滚或刷新。
3. **原因**：安全、可理解的原因类别；不直接展示原始系统错误。
4. **动作**：重试、重新授权、改选批准来源、取消、回滚、等待恢复或暂不可用。

以下事实必须保持区分：

| 事实 | 用户可见含义 |
|---|---|
| 请求已取消 | 只表示用户取消意图已被接受；清理/回滚未确认前不能显示“已取消完成”。 |
| 任务完成 | 只表示任务有终态；必须同时显示业务 outcome，不能泛化为成功。 |
| 日志写入成功 | 只表示诊断事实已保存；不能提升业务状态。 |
| 发现备份或临时文件 | 只表示存在恢复材料；不能显示恢复已完成。 |
| `recoveryRequired` | 显示当前不能继续同目标操作，并提供恢复/查看日志动作。 |
| `Unavailable` | 显示资源、权限、来源或适用范围原因，不显示可应用按钮语义。 |

## 6. 隐私和敏感信息规则

### 6.1 允许记录的安全摘要

- 固定 Game ID、方案 ID、背景组 ID、任务/流程关联标识。
- `officialGitHub` 或预置镜像的批准来源 ID；不记录完整请求 URL。
- 已批准的 Wine 版本身份、架构、资源状态和安全的 HTTP 状态类别。
- 阶段、结果、非敏感原因类别、退出码、信号、耗时、字节数、条目数量、资源数量和清理结果。
- 文件/路径的安全类别或不透明位置标识；不得让其还原完整本机位置。
- metadata/manifest 的身份和校验结果摘要；不记录完整清单或游戏文件内容。

### 6.2 禁止记录和导出

- 密码、Token、Cookie、Authorization header、私钥、签名 URL、带敏感 query 的完整 URL、认证响应正文。
- 完整用户目录、完整游戏目录、完整 prefix 路径、bookmark 字节、security-scoped 授权材料或可恢复授权的内容。
- 游戏文件内容、旧反作弊文件内容、hosts 实际规则、完整命令行、环境变量、脚本正文、转储内容。
- `config.ini` 原始 value、个人设置值、账号标识、用户输入的自由文本、截图、视频和其他个人数据。
- 未经 Product 明确批准的网络响应正文、崩溃转储或大块二进制数据。

`config.ini` 在产品界面中的原始字段展示，不改变诊断日志禁止记录原始 value 的规则。隐私清理必须发生在本地持久化和导出之前，不能只依赖用户界面隐藏。

### 6.3 数据流边界

- 当前版本只承诺本地诊断日志；不自动上传、远程遥测、后台提交或把日志发送到第三方服务。
- 用户导出是用户主动动作；导出包只能包含经过相同隐私规则清理的诊断事实。
- 日志保留应有边界并允许清理；不承诺无限期历史、全量追踪或可恢复的删除文件。
- 日志写入或导出失败必须被记录为诊断能力失败，并提示可能不完整；不能修改或掩盖原业务结果。

## 7. Must / Should / Deferred / Out of Scope

| 优先级 | 日志能力 | 当前版本状态 | 产品边界 |
|---|---|---|---|
| Must | 核心流程诊断事件 | In Scope | 覆盖本文件第 4 节全部流程的关键阶段、结果和失败事实。 |
| Must | 失败/取消/不可用/恢复上下文 | In Scope | 必须有原因类别、阶段、关联作用域和恢复/下一步事实。 |
| Must | 用户错误与诊断日志分层 | In Scope | 用户错误安全可行动；诊断日志可排障；两者不能互相伪造成功。 |
| Must | 本地隐私清理 | In Scope | 持久化和导出前均禁止敏感信息；不记录密码、Token、完整路径、内容或个人数据。 |
| Must | `WineReady`、prefix、启动和完整性状态可追踪 | In Scope | 日志只能反映业务真实门槛，不得以日志存在替代门槛。 |
| Should | 用户主动查看/导出诊断日志 | In Scope | 继续支持当前产品已有的日志导出目标；导出内容安全且不自动上传。 |
| Should | 日志按用户问题提供可读的阶段摘要 | In Scope | 提升排障效率，但不新增自由查询、复杂分析或开发工具平台。 |
| Deferred | 面向开发者的详细调试级别、可配置过滤、长期分析和高级检索 | Future | 不作为当前版本用户能力或验收门槛。 |
| Deferred | 远程诊断、自动上传、崩溃数据服务和用户授权后的持续遥测 | Future | 当前版本不建立外部日志服务或账号关联。 |
| Out of Scope | 密码/Token/完整路径/游戏文件内容采集 | Out of Scope | 任何排障便利都不能覆盖隐私禁止规则。 |
| Out of Scope | 以日志数量、日志文件大小或“写过一条日志”证明功能完成 | Out of Scope | 产品验收以覆盖事实和安全上下文为准。 |

## 8. Review、Performance 和用户验证追溯

| 输入来源 | 日志产品映射 | 关闭边界 |
|---|---|---|
| P1-01 bookmark scope/stale | 记录 resolve、stale、refresh、writeback、scope pairing 和 revoked access 结果。 | 不记录 bookmark 内容；真实 NSOpenPanel 仍需用户验证。 |
| P1-02 裸 path / managed path | 记录路径授权/身份门禁的结果和失败类别，不记录完整路径。 | 日志不能替代 API 边界修复和越界测试。 |
| P1-03 config/pkg metadata | 记录解析、mapping、size/MD5、冲突和不支持结果摘要。 | 不记录原始 config value 或完整 JSON Lines；真实渠道样本仍需验证。 |
| P1-04 Wine prefix readiness | 记录 binary/version/prefix 准备和 readiness gate 结果。 | 未准备 prefix 不能由日志显示成 `WineReady`。 |
| P1-05 TaskReceipt/lock | 记录任务关联、资源冲突、取消传播和 recovery-held lock。 | 日志不能代替真实并发和中断验证。 |
| P1-06 HTTP/network | 记录来源 ID、状态类别、超时、redirect/403/429、空目录和 asset 结果。 | 不记录认证或签名 URL；真实网络仍需用户验证。 |
| P1-07 cleanup boundary | 记录清理目标的安全身份、阶段、越界拒绝和清理结果。 | 不记录完整 cleanup path；不能因有日志而关闭安全边界缺陷。 |
| P1-08 Accessibility | 为动态启动、失败、取消、恢复状态提供与 UI 同源的安全状态事实。 | 日志不能替代 AX tree、VoiceOver、键盘和动态 notification 验证。 |
| P2-01 signed entitlements | 记录用户授权/能力不可用等安全错误类别。 | 日志不能证明签名、Sandbox 或 entitlements 通过。 |
| P2-02 cancellation cleanup | 记录取消请求、实际终态、cleanupVerified/recoveryRequired 和时序失败。 | Release 取消稳定性仍需专门测试。 |
| P2-03 Settings projection | 记录 readiness error、notSelected、notDownloaded、catalog 和 refresh outcome 的区分。 | 不把日志摘要当成 Settings UI projection 通过。 |

## 9. Product 验收标准

1. 本文件第 4 节每个核心流程都能产生安全的阶段和结果事实；不要求每个内部函数单独记录。
2. 每个失败、取消、不可用、未支持和恢复未完成结果都能追踪到操作、阶段、原因、作用域和恢复事实。
3. 用户可见错误与诊断日志均不泄露密码、Token、完整路径、bookmark、游戏文件内容或个人数据。
4. 日志不能把任务完成、日志写入、目录存在、部分下载或开发调试输出提升为业务成功。
5. `WineReady`、prefix、启动退出、完整性、兼容方案、背景和 Settings 的诊断事实与 Product 状态一致。
6. Review P1/P2 和用户验证映射项能从日志确认“发生了什么”，但需要的真实权限、签名、UI、网络和 Wine 证据仍必须单独完成。

- Implementation 只实现本文件的 Must 记录事实和现有 Should 导出边界；不得新增远程遥测、任意日志上传或敏感信息采集。
