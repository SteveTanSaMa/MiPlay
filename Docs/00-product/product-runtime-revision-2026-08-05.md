# MiPlay 运行时产品语义修订

> **文档状态**：已冻结（本阶段 Product 回溯）
> **产品阶段**：Product Definition（问题空间定义）
> **当前版本边界冻结**：2026-08-05
> **适用范围**：Wine 版本发现、获取、安装、选择、就绪和设置页设备信息

## 1. 修订结论

当前版本只支持 **MiPlay 托管 Wine**。MiPlay 可以从默认官方 GitHub 或预置可信镜像 allowlist 获取 Wine，并负责记录、安装、选择和就绪判定。系统 Wine、Whisky、CrossOver 或其他本机 Wine 不属于候选运行时：不检测、不展示、不导入、不复用，也不作为失败后的 fallback。

当前版本不允许用户自由输入 URL。用户只能在产品发布时冻结的批准来源中选择；默认来源为官方 GitHub。来源选择失败不能伪造成功，不能静默改用未批准来源，也不能静默切换到本机 Wine。

本文件解决的是产品语义，不声明当前代码、网络下载或真实 Wine 启动已经通过。GitHub 请求超时、Wine 资产只完成部分下载、用户验证未通过，均不能形成“已安装”或 `WineReady` 的证据。

## 2. 唯一的“当前运行时”定义

### 2.1 产品定义

“当前运行时”唯一表示：

> **当前选中游戏实际尝试使用的 MiPlay 托管 Wine 版本身份，加上该游戏对应的就绪结果。**

它是一个面向当前游戏的状态事实，不是一个泛指的本机 `wine` 文件，也不是一个全局机器状态。当前运行时必须同时说明“是哪一个托管版本”和“对当前游戏是否就绪”。

### 2.2 用户应当能够区分的事实

| 产品事实 | 准确定义 | 是否足以称为当前运行时就绪 |
|---|---|---|
| 来源目录中的可用版本 | 来自官方 GitHub 或批准镜像的、身份和资源可验证的版本条目 | 否；远程目录不代表本地存在 |
| 下载目标 | 用户或启动流程正在获取的批准版本 | 否；传输中或部分资源不构成运行时 |
| 已校验资源 | 下载完成且内容校验通过、等待安装提交的资源 | 否；仍未形成已安装版本 |
| 已安装版本 | MiPlay 管理范围内已完成安装、身份可复核且安装记录可重读的版本 | 否；未必被当前游戏选中或就绪 |
| 当前游戏选中版本 | 当前 Game ID 绑定的已安装托管版本 | 否；还必须通过该游戏的 readiness |
| 当前运行时 | 当前游戏选中版本的身份、来源、安装状态和该游戏 readiness 的组合 | 只有 readiness 为 `WineReady` 时才可支持启动 |
| 本机可执行文件 | 机器上任意位置存在的 Wine 或 Wine wrapper | 永远不是 MiPlay 当前运行时 |

### 2.3 当前运行时的产品展示边界

当前运行时相关信息应分别表达以下事实：

1. **显示名称和版本身份**：展示批准来源中可识别的 Wine 名称与版本身份；版本名不能替代安装或就绪状态。
2. **来源**：展示“官方 GitHub”或预置 allowlist 中的镜像名称；不展示任意来源为受支持来源。
3. **安装状态**：明确未安装、获取中、安装中、已安装、失败、已取消或需要恢复。
4. **当前选中状态**：明确该版本是否为当前游戏的选中版本。下载目标不自动成为选中版本。
5. **当前游戏 readiness**：明确该版本对当前游戏是 `WineReady`、未就绪、不可用或等待恢复。
6. **路径**：运行时路径不是默认用户文案。受控诊断可以记录安全的身份摘要；产品展示不得要求用户理解或复制路径来判断是否可用。

当没有当前游戏、没有选中版本、选中版本未安装或 readiness 未通过时，产品必须如实显示对应的未就绪事实，不得用一个 Wine 名称或路径制造“当前运行时可用”的印象。

## 3. Wine 版本与来源语义

### 3.1 来源策略

| 来源 | 产品状态 | 规则 |
|---|---|---|
| 官方 GitHub Release | 支持，默认 | 版本目录和资源身份通过产品批准范围后，才能进入获取流程 |
| 预置可信镜像 allowlist | 支持，可选 | 只允许选择发布时冻结的镜像 ID；镜像资源仍须经过同样的身份、内容和安装验证 |
| 系统 Wine | 禁用 | 不检测、不展示、不导入、不复用 |
| Whisky / CrossOver 管理的 Wine | 禁用 | 不检测、不展示、不导入、不复用 |
| 用户自由输入 URL 或 allowlist 外来源 | 禁用 | 不提供输入，不保存、不请求、不下载、不重试 |

来源是 Wine 运行时的产品属性，不改变官方游戏安装仍为 Deferred 的边界。MiPlay 管理的是 Wine，不托管游戏客户端安装包。

### 3.2 “可用版本”的产品定义

当前版本的“可用版本”指：批准来源目录中，版本身份、目标资源和适用架构均能被验证，且允许 MiPlay 发起获取的版本。它只说明该版本可作为获取目标，不说明本机已有安装，也不说明当前游戏可启动。

以下内容都不足以产生“可用版本”或 `WineReady`：

- 远程目录出现版本名称；
- API 返回成功或 HTTP 200；
- 下载进度达到 100%；
- 资源文件存在或解压目录存在；
- 任意位置存在 `wine` 可执行文件；
- `wine --version` 能返回文本；
- 代码入口、状态枚举、日志或备份记录存在。

### 3.3 “已安装版本”的产品定义

版本只有在以下产品门槛全部满足后才是“已安装”：

- 资源已完整获取并通过内容校验；
- 安装或解压结果位于 MiPlay 管理范围内；
- MiPlay 管理的可执行文件身份能够被验证，并与版本记录一致；
- 安装提交已经完成；
- 重新读取持久化记录后，版本身份和安装事实仍一致。

下载结束而找不到 MiPlay 管理的可执行文件、身份不一致、安装提交失败或重读失败，均为安装失败。该版本不得进入已安装集合、当前选中集合或 `WineReady`。

### 3.4 “当前选中版本”的产品定义

“当前选中版本”是与一个 Game ID 绑定的、已经形成安装事实的 MiPlay 托管版本。选择意图、下载目标、正在安装版本和上一次有效版本必须区分：

- 新版本在下载或安装阶段不是当前选中版本；
- 安装失败或取消不得覆盖此前有效的当前选中版本；
- 当前选中版本失效时，必须显示未就绪或需要恢复，不得自动选择外部 Wine；
- 选中版本存在不等于该版本对当前游戏已 `WineReady`。

## 4. 当前游戏 readiness 语义

`WineReady` 是 **当前游戏级** 的 readiness 结果，而不是全局“机器有 Wine”的结论。只有以下事实同时成立，当前游戏才可为 `WineReady`：

1. 版本来源属于当前版本批准范围；
2. 版本已经由 MiPlay 完成安装并通过身份复核；
3. 该版本确实被当前 Game ID 选中；
4. 版本身份、安装记录和托管副本保持一致；
5. 当前游戏对应的 MiPlay 管理运行环境已准备完成，并通过当前版本启动前置校验。

真实 Wine 运行和游戏进程启动仍需用户验证；用户验证完成前，不能把日志、文件存在或静态检查当作真实启动证据。

| readiness 结果 | 产品含义 | 启动语义 |
|---|---|---|
| `WineReady` | 当前选中托管版本对当前游戏满足全部就绪门槛 | 允许进入启动流程 |
| `SelectedNotReady` | 有选中版本，但 prefix、运行环境、身份或启动前置校验未通过 | 阻止启动并显示可修复原因 |
| `NoSelectedRuntime` | 当前游戏没有选中已安装托管版本 | 阻止启动，引导获取或选择批准版本 |
| `RuntimeUnavailable` | 版本来源、资源、权限或适用性不满足 | 不提供可应用或可启动语义 |
| `RecoveryRequired` | 上一次下载、安装、删除或取消的副作用尚未收敛 | 阻止同一目标继续操作，先完成恢复 |

## 5. 下载、安装、失败、取消和恢复

| 阶段或结果 | 产品定义 | 对已安装/选中事实的影响 |
|---|---|---|
| `Available` | 远程批准目录中可验证的获取目标 | 不创建本地安装或选中事实 |
| `Downloading` | 同一来源、版本和资源目标正在传输 | 不创建已安装或选中事实 |
| `DownloadFailed` | 传输超时、限流、重定向无法验证、部分资源或内容验证失败 | 不产生新安装；保留此前有效版本 |
| `ArtifactReady` | 资源完整且内容验证通过，等待安装提交 | 仍不产生已安装或选中事实 |
| `Installing` | 正在完成安装、身份复核和提交 | 不得展示为已安装或 `WineReady` |
| `Installed` | 安装提交和重读确认完成 | 可以成为某个游戏的选中候选 |
| `InstalledNotSelected` | 已安装，但未绑定到当前游戏 | 当前游戏不能因此报告 `WineReady` |
| `SelectedNotReady` | 已绑定到当前游戏，但 readiness 未通过 | 阻止启动 |
| `WineReady` | 已安装、已选中且当前游戏 readiness 通过 | 允许进入启动流程 |
| `InstallFailed` | 安装、可执行文件身份、提交或重读验证失败 | 不创建新安装/选中事实；清理结果另行表达 |
| `Cancelled` | 用户取消已被处理，且必要的临时资源清理或恢复已确认 | 未提交的新目标不进入安装；已有有效版本继续保留 |
| `RecoveryRequired` | 取消或失败已经产生副作用，但清理/恢复尚未确认完成 | 阻止同一目标继续下载、安装或启动 |
| `Unavailable` | 批准来源、资源、权限或适用范围不满足 | 不展示可应用或可启动语义 |

下载进度、预计大小、速度和阶段必须属于同一下载目标。预计大小未知时，不得伪造确定百分比；速度必须代表连续传输样本，不能固定显示 0 或虚构速度。状态刷新不得把当前目标重置成另一个版本，也不得把刷新中的中间状态压平为“已完成”。

如果当前来源目录刷新后不再列出某个本地已安装版本，不能直接删除或隐藏该安装事实。应保留为“已安装但当前目录未列出/当前不可获取”，同时阻止其在未经重新验证前产生新的 `WineReady` 结论。

## 6. 设置页设备信息边界

Mac 型号、macOS 版本和磁盘空间是设置页的只读信息能力，不属于 Wine 版本状态，也不决定 `WineReady`。

| 信息 | 产品定义 | 读取失败语义 |
|---|---|---|
| Mac 型号 | 只展示系统报告提供的型号文本，不从芯片或架构自行推断 | 显示不可用，保留读取失败事实 |
| macOS 版本 | 只展示系统报告提供的版本字符串 | 显示不可用，不能以旧值替代 |
| 磁盘空间 | 展示与 MiPlay 托管 Wine 下载/安装目标相关卷的当前空间信息 | 显示不可用，不能用无关卷、0、空值或路径推断结果冒充准确值 |

设备信息读取失败不会自动改变 Wine 版本状态，也不会允许或阻止启动；它只说明设置页信息不可用。

## 7. 用户问题与 Issue 追溯

| Issue | 产品要求 | 当前版本验收边界 |
|---|---|---|
| `DL-001` | 下载状态在同一目标上保持稳定，用户看到的阶段、版本和结果不能在刷新时快速跳变 | Product 只冻结状态投影必须保持同一目标和终态事实；具体刷新和动画由 UX/UI/Implementation 负责 |
| `DL-002` | 下载进度、预计字节、速度和结果必须真实对应目标资源 | 完成必须有可解释的传输结果；未知大小不报确定百分比，固定 0 或虚假速度不算通过 |
| `DL-003` | 下载后必须能确认 MiPlay 托管的 Wine 可执行文件身份 | 找不到、身份不一致或无法读回均为 `InstallFailed`，不得进入 `Installed`、选中或 `WineReady` |
| `INFO-001` | “当前运行时”固定表示当前游戏选中的托管版本及其 readiness | 名称、版本、来源、安装、选中和 readiness 必须分层表达；路径不是默认语义 |
| `INFO-002` | 可用、已安装、已选中版本的刷新结果不能互相替代 | 远程目录刷新不删除本地安装事实；失败、取消和恢复保留此前有效版本 |
| `INFO-003` | 设置页设备信息必须来自准确的系统报告事实 | 型号和系统版本不推断；错误不伪造旧值；磁盘空间指向托管 Wine 目标卷 |
| `INFO-004` | 磁盘空间失败必须是明确的不可用事实 | 不以 0、空值或其他卷数据报告成功；不改变 Wine readiness |
| `STRUCT-001` | 下载、安装、选中和 readiness 是可区分的产品阶段 | 任何阶段不得单独提升为 `WineReady`；取消/失败后的副作用必须进入恢复语义 |
| `ARCH-001` | 状态语义在拆分实现后仍必须保持一致 | Product 不规定文件拆分方式；下游必须维持本矩阵，且遵守单文件不超过 500 行的既有工程约束 |

## 8. 与既有 Product 和 Review 结论的冲突登记

| 旧口径 | 冲突原因 | 2026-08-05 后有效口径 |
|---|---|---|
| `WineReady` 是 Global 状态 | 无法表达不同游戏、不同 prefix 或选中版本的 readiness 差异 | `WineReady` 是当前 Game ID 级结果；Wine 版本安装事实与 readiness 分开 |
| 用户无需感知 Wine 的存在 | 与用户需要判断当前运行时状态相冲突 | 用户无需理解 Wine 技术，但可以看到安全的名称、版本、来源和状态事实 |
| 机器上存在 Wine 即可作为运行时线索 | 会把系统 Wine、Whisky 或 CrossOver 误认为受支持 | 只有 MiPlay 托管、身份一致、已选中且当前游戏 readiness 通过才有启动语义 |
| 下载完成等于 Wine 可用 | 忽略安装、可执行文件身份、持久化和 prefix | 下载、已安装、已选中和 `WineReady` 各自独立验收 |
| 远程 catalog 版本就是可用版本 | 目录条目不代表本地安装或可启动 | `Available` 只代表批准获取目标 |

Review 的下载、安装、prefix、权限和真实启动缺口继续有效。当前 Product 只冻结验收定义，不能用代码入口、日志、目录存在、HTTP 成功或部分网络结果关闭这些缺口。用户验证通过前，Release 不得把本文件矩阵标记为已完成。

本修订采用 Research 已确认的产品边界：远程 catalog 条目不等于本地运行时，下载完成不等于安装成功，托管 executable 身份、持久化重读和当前游戏运行环境都需要分别确认。Research/Review 未提供的具体技术字段含义不由本 Product 文档补充。

## 9. Must / Deferred / Out of Scope

| 优先级 | 产品能力 | 当前版本状态 |
|---|---|---|
| Must | MiPlay 托管 Wine-only、官方 GitHub 默认来源、allowlist 镜像选择、禁止任意 URL | 当前版本验收范围 |
| Must | 当前运行时的名称、版本、来源、安装状态、选中状态和当前游戏 readiness 语义 | 当前版本验收范围 |
| Must | 可用/下载中/已安装/选中/`WineReady`/失败/取消/恢复状态区分 | 当前版本验收范围 |
| Must | 下载后托管 executable 身份验证和安装提交边界 | 当前版本验收范围 |
| Should | 设置页 Mac 型号、macOS 版本和目标卷磁盘空间的准确只读展示 | 当前版本产品范围，具体优先级沿用 `product-features.md` |
| Deferred | 官方游戏安装、自定义启动参数、帧率解锁、截图/视频目录入口 | 不进入本轮 Implementation 或 Release 验收 |
| Deferred | Retina、Steam patch / Steam 白名单、旧版反作弊文件替换、Metal HUD、左 Command 映射 Control、hosts 屏蔽 | 属于当前版本目标但本轮暂缓实现；不得显示为已实现或可应用 |
| Out of Scope | 系统 Wine、Whisky、CrossOver 或用户任意来源的检测、导入、复用和 fallback | 永不成为当前版本运行时 |

## 10. Product 验收声明

本修订完成的验收仅表示产品边界和术语已经冻结。下游必须分别证明：批准来源可用、下载结果真实、托管安装完成、可执行文件身份可复核、当前游戏 readiness 通过，以及失败/取消/恢复状态正确收敛。任何一个门槛缺失，都只能报告对应的未就绪或失败状态，不能用另一个状态替代。
