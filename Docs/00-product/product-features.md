# MiPlay 功能范围与产品边界

> **文档状态**：已冻结（Freezed）
> **产品阶段**：Product Definition（问题空间定义）
> **当前版本边界冻结**：2026-08-04

## 1. 功能范围（Feature List）

### 【Must（必须）】

- **游戏启动** — 用户可以选择已添加的游戏并发起启动请求。
- **Wine 版本管理** — 仅使用 MiPlay 托管的 Wine 运行时；Wine 来源支持默认官方 GitHub 与预置可信镜像 allowlist 的选择，禁止自由输入 URL。MiPlay 不提供本机 Wine、Whisky 或 CrossOver Wine 的检测、导入或复用功能。
- **当前运行时状态** — 对当前选中游戏，明确展示 MiPlay 托管 Wine 的身份、来源、版本、安装状态和该游戏的就绪状态；不把路径或下载完成当作运行时就绪。
- **Wine 版本状态管理** — 区分来源目录中的可用版本、已完成托管安装的版本和当前选中的版本；失败、取消或恢复未完成时保留正确的状态边界。
- **内置兼容方案应用** — 将当前版本发布清单中的、通过资源与权限能力检查的社区兼容方案应用到系统中，解决已知类别的启动问题；发布清单外的方案不构成当前版本能力。
- **游戏状态总览** — 展示各款米哈游游戏的基本状态（如：未安装、已就绪、运行中、需更新）。
- **定位已安装游戏路径** — 用户告知 MiPlay 各游戏的可执行文件所在路径。三款游戏从启动起即在系统中可见，无需手动"添加"。
- **游戏文件完整性校验** — 检查游戏客户端文件是否完整，发现异常时告知用户。
- **诊断日志捕获** — 对当前版本核心流程记录可追踪的阶段、结果、失败原因和恢复上下文；日志不得记录密码、Token、完整用户路径、游戏文件内容或个人数据。
- **版本背景组切换** — 每款游戏可在其有效的官方版本背景组之间切换，切换只影响目标游戏。
- **按游戏独立设置** — 每款游戏拥有独立的设置范围；`config.ini` 展示原始字段和值，不猜测字段含义。

### 【Should（应该）】

- **版本检测与更新提示** — 检测游戏当前版本与官方最新版本的差异，并在有新版本时提示用户；不包含由 MiPlay 执行完整游戏更新包下载和安装。
- **多语言支持** — 至少支持中文和英文界面语言。
- **日志导出** — 用户可导出当前版本的安全诊断日志用于自行排障或社区求助；不自动上传，不包含敏感信息。
- **设置页设备信息** — 在设置页展示系统报告的 Mac 型号、macOS 版本和与 MiPlay 托管 Wine 目标相关的磁盘空间信息；读取失败时显示不可用，不用猜测值替代。

### 【Deferred（延期实现；与当前版本范围分开记录）】

> 本节中的功能分为两类：明确移出当前版本的 Future 功能，以及仍属于当前版本目标但本轮暂缓实现的高级配置。Deferred 不能被标记为已完成。

- **官方游戏安装引导** — 未来可对接米哈游官方资源，完成客户端获取、安装和校验；当前版本以定位已安装游戏路径为准。
- **自定义启动参数** — 未来可允许高级用户指定额外启动参数；当前版本不作为验收要求。
- **帧率解锁** — 未来可针对特定游戏提供游戏级帧率上限解除；当前版本不作为验收要求。
- **未纳入本次产品目标的兼容方案扩展** — 未来可增加新的已验证方案类型；本版本只验收本文件发布清单和明确列出的 Deferred 目标。
- **截图/视频文件夹快捷入口** — 未来可快速打开游戏对应的媒体目录；当前版本不提供该入口。
- **高级配置 A-01：Retina** — 属于当前版本目标，本轮 Deferred 实现；未完成前不得标记为已实现。
- **高级配置 A-02：Steam patch / Steam 白名单启动** — 属于当前版本目标，本轮 Deferred 实现；未完成前不得标记为已实现。
- **高级配置 A-03：旧版反作弊文件替换** — 属于当前版本目标，本轮 Deferred 实现；未完成前不得标记为已实现。
- **高级配置 A-04：Metal HUD** — 属于当前版本目标，本轮 Deferred 实现；未完成前不得标记为已实现。
- **高级配置 A-05：左 Command 映射 Control** — 属于当前版本目标，本轮 Deferred 实现；未完成前不得标记为已实现。
- **高级配置 A-06：hosts 屏蔽** — 属于当前版本目标，本轮 Deferred 实现；未完成前不得标记为已实现。

### 【Won't（不做）】

- **账号管理** — 不处理任何账号密码、登录凭据或会话管理。
- **游戏文件托管** — 不缓存、存储或提供游戏客户端安装包文件；安装过程通过官方资源获取。
- **反作弊程序文件破解** — 不修改、绕过或破坏反作弊程序文件本身；兼容方案仅利用反作弊已有特性或替换已知旧版本，而非破解。
- **游戏 Mod 管理** — 不支持任何形式的游戏模组安装或管理。
- **游戏内画质设置** — 不提供帧率、画质、图形细节等游戏内画质设置（由游戏自身管理）。
- **多用户切换** — 不支持系统多用户环境下的用户切换功能。
- **游戏内覆盖功能** — 不提供任何游戏内覆盖（Overlay）、截图、录屏等功能。
- **社区论坛或社交功能** — 不内置用户间交流、评论或评分能力。
- **通用 Wine 版本管理器** — Wine 版本管理仅面向指定三款米哈游游戏启动所需的范围，不提供面向任意 Windows 游戏的通用 Wine 版本管理与切换能力。
- **非米哈游游戏支持** — 仅面向米哈游旗下三款指定游戏（原神、星穹铁道、绝区零），不支持这三款之外的任何游戏。
- **自主更新** — 不内置自动更新机制（系统更新策略由操作系统管理）。

### 2.1 当前版本兼容方案发布清单（冻结）

当前版本产品目标与“本轮可发布清单”分开记录。五项既有方案不全部进入本轮可发布清单：`CS-01` 保留为有条件发布项；`CS-02`、`CS-03`、`CS-04` 对应用户明确纳入的高级目标，但本轮 Deferred；`CS-05` 没有对应的当前版本用户需求，排除在当前版本之外。该收敛是 Product Agent 的版本范围决策，不得由 Implementation Agent 自行扩大或缩减。

“发布清单”只表示本轮允许进入产品验收的方案；“当前版本目标”不表示本轮已经发布。对任何方案，“可应用”仅表示：目标资源存在、适用游戏匹配、所需系统权限能够被实际授予，并且方案可以在应用后完成后置验证和回滚。能力检查未通过时，方案不得被标记为可应用，也不得进入应用流程；静态定义、列表展示、代码入口和备份成功都不能替代真实执行。

| 方案 ID / 名称 | 适用游戏 | 当前版本产品范围 | 本轮发布清单 | 当前产品决策 |
|----------------|---------|------------------|--------------|--------------|
| `CS-01 modify_hostname` / 修改 Hostname | 原神、星穹铁道、绝区零 | In Scope | **是，条件可用** | 仅在权限能力、原值备份、真实修改、读回验证和回滚证据齐全时可应用；当前 Review/用户验证尚未替代这些证据。 |
| `CS-02 block_network_anticheat` / hosts 屏蔽 | 原神、星穹铁道、绝区零 | In Scope（对应 A-06） | **否，Deferred** | 用户已纳入当前版本目标；本轮暂不实现。没有真实资源或权限支持时不得展示为可应用。 |
| `CS-03 replace_old_anticheat` / 旧版反作弊文件替换 | 原神、星穹铁道、绝区零 | In Scope（对应 A-03） | **否，Deferred** | Review 确认当前缺少可随版本交付的真实旧版资源；目标保留但本轮不得展示为可应用。 |
| `CS-04 steam_whitelist` / Steam patch / Steam 白名单启动 | 原神 | In Scope（对应 A-02） | **否，Deferred** | Review 确认当前缺少真实 Steam 标识、资源与配置交互支持；目标保留但本轮不得展示为可应用。 |
| `CS-05 use_legacy_patch` / 使用旧版兼容补丁 | 绝区零 | **Out of Scope** | **否** | 用户最新范围明确的是 Steam patch 和旧版反作弊文件替换，不是该额外旧版 DLL 补丁；其资源缺口也不允许借代码入口补足。 |

因此，本轮兼容方案发布清单仅包含 `CS-01`，且它也只有在资源、权限、后置验证和回滚条件全部满足时才可应用。`CS-02` 至 `CS-05` 不得在本轮显示为可应用，也不得被记为 `Applied`。这不是 Implementation 对能力的私自删减，而是对当前用户范围和 Review 证据状态的 Product 冻结。

这份清单定义的是本轮发布验收目标，不是当前代码已通过的声明。Review 已指出真实权限、托管 Wine、网络和用户验证仍有缺口；在证据完成前，Release 不得将 `CS-01` 标记为通过。

### 2.2 兼容方案应用状态语义

- `Applying`：应用过程正在进行；不代表任何后置条件已经满足。
- `Applied`（代码语义为 `.applied`）：仅在真实操作完成、后置状态读取验证通过、应用记录已保存且回滚所需的原始状态仍可用时成立。用户点击应用、任务入队、代码分支执行、备份成功或日志成功均不得直接产生 `Applied`。
- `Failed`：执行或后置验证失败。若操作已经改变目标状态，必须先尝试恢复；恢复失败时仍不得标记 `Applied`，并须保留失败与恢复不完整事实。
- `RolledBack`：已恢复到应用前状态，并通过与原始状态的对照验证。回滚完成不是应用成功的替代状态。
- `Unavailable`：资源、适用范围或权限能力检查不满足。该状态不得提供“应用”语义，也不得创建 `Applied` 记录。

### 2.3 产品验收矩阵

| 验收对象 | 成功标准 | 失败标准 | 验证标准 | 回滚 / 恢复标准 |
|---------|---------|---------|---------|----------------|
| CS-01 修改 Hostname | 目标 Hostname 实际变更为方案规定格式；重新读取的目标值与预期一致；原始 Hostname 已保存；随后才可记录 `Applied`。 | 权限不足、原值无法保存、写入报错或读回不一致，均为失败；若已发生部分变更，不能静默继续。 | 应用前确认适用游戏与权限能力；应用后重新读取 Hostname，并确认仅声明的系统值发生变化。 | 从保存的原始值恢复全部受影响的 Hostname 值；恢复后重新读取并与原值一致，才可记为 `RolledBack`。 |
| A-02 Steam patch / Steam 白名单 | **Deferred**；未来只有在真实 Steam 资源/标识可交付、实际状态可读回且回滚可验证时才可进入发布清单。 | 当前轮次没有成功标准可供验收；未验证资源、目录检测或日志不得标记可应用。 | 下游重新提出发布时，必须验证实际目标状态、适用游戏和配置结果。 | 应恢复到应用前状态并读回确认；未实现时不创建应用记录。 |
| A-03 旧版反作弊文件替换 | **Deferred**；未来只有在真实旧版文件随版本交付、替换结果可读回且原文件可恢复时才可进入发布清单。 | 缺少真实文件、只有备份路径或只有代码入口，均不得标记可应用。 | 下游重新提出发布时，必须验证文件身份、目标内容和适用版本。 | 恢复应用前文件并通过内容/身份复核；未实现时不创建应用记录。 |

| 完整性校验 | 取得非空 manifest，且其游戏标识、客户端版本与目标安装版本对应；manifest 中每个必需文件存在且内容校验通过；全部通过后才可报告完整。 | 任一文件缺失或内容不匹配均为失败；manifest 不支持、为空、缺失、版本不对应或无法验证时为“无法判定/不支持”，绝不能报告通过。 | 验证 manifest 非空、版本对应关系和全部条目结果；仅检查关键可执行文件存在、代码入口或 SHA-256 分支存在均不构成通过。 | 完整性校验本身不修改游戏文件，不适用兼容方案式回滚；失败或不支持时保留异常结果，不得把游戏状态提升为完整/已就绪。 |

### 2.6 Wine 来源策略与当前版本验收矩阵

#### 2.6.1 来源策略（当前版本冻结）

当前版本只支持 **MiPlay 托管的 Wine**。这里的“托管”是产品语义：MiPlay 从批准来源取得版本，保存到 MiPlay 管理范围，记录其版本身份，并对该副本执行后置验证。用户无需理解 Wine 的技术构成，但可以查看当前运行时的安全名称、版本、来源和就绪状态。机器上“能找到一个 `wine` 可执行文件”不等于该运行时被 MiPlay 支持。MiPlay 不检测、不展示、不导入、不复用本机或第三方 Wine。

| 来源类别 | 当前版本决策 | 允许用途 | 不允许用途 |
|---------|--------------|---------|-----------|
| 官方 GitHub Release | **支持，默认来源** | 由 MiPlay 获取、安装、选择和验证；通过验收后用于游戏启动 | 不得把仅出现在远程列表中的版本直接视为可用 |
| 预置可信镜像 allowlist | **支持，可选来源** | 用户可从预置列表选择；MiPlay 获取、安装、选择和验证后用于游戏启动 | 不得由用户输入任意 URL；allowlist 外镜像不得进入来源选择 |
| 系统 Wine、Whisky、CrossOver 或其他本机 Wine | **禁用，不检测** | 无 | 不读取、不展示、不导入、不复用，不得进入可用版本集合、`WineReady`、启动或兼容方案 |
| 用户自定义 URL 或未批准来源 | **禁用，不提供输入** | 无 | 不得保存、请求、下载、重试或静默替代批准来源 |

当前批准上游为 `yaagl/anime-game-wine` 的 GitHub Releases；镜像只允许来自产品发布时冻结的可信 allowlist。allowlist 是产品范围约束，远程版本列表不能自行扩大该范围。这里的 artifact 身份与用户安装的 CrossOver.app wrapper 无关。该来源策略只涉及 Wine 运行时，不改变官方游戏安装及其他 Deferred 边界。

来源选择和失败语义：

1. 默认选择官方 GitHub；用户可以改选预置 allowlist 中的可信镜像，但不能自由输入 URL。
2. 选定来源返回空目录、超时、限流、重定向后无法验证、资源下载不完整或内容验证失败时，结果必须是失败或不可用，不得报告下载/安装成功。
3. 失败不得静默切换到系统 Wine、Whisky、CrossOver 或 allowlist 外来源。用户只能重试当前批准来源，或主动选择另一项预置来源。
4. 已有有效的 MiPlay 托管版本可以继续保留；新来源失败不能把未完成资源写入可用版本，也不能覆盖已有有效选择。

#### 2.6.2 “可用版本”的产品定义

一个 Wine 版本满足第 1 项时，才是当前版本可获取的“可用版本”；第 2 项至第 5 项分别定义从资源、安装、选中到当前游戏 `WineReady` 的后续门槛：

1. 版本身份属于当前版本 allowlist，来源记录、目标架构和下载资源对应；仅有版本名称、API 列表或 `wine --version` 输出不够。
2. 资源由 MiPlay 从批准来源取得，并完成内容完整性验证；这形成已校验资源，不自动形成已安装事实。
3. 安装、托管 executable 身份验证、持久化提交和重读完成后，才形成已安装事实。
4. 版本被当前 Game ID 选中，且运行时身份、安装记录和托管副本相互对应。
5. MiPlay 管理的当前游戏运行环境准备完成并通过启动前置验证后，才可报告当前游戏 `WineReady`；外部 Wine 的二进制 smoke pass、系统路径存在或既有 bottle 存在均不能替代这一验证。

#### 2.6.3 Wine 验收矩阵

| 验收对象 | 成功标准 | 失败 / 禁止通过标准 | 验证证据 | 状态与恢复标准 |
|---------|---------|-------------------|---------|----------------|
| 批准来源版本发现 | 返回官方 GitHub 或 allowlist 镜像中、架构匹配且具有可验证资源身份的版本记录 | 任意外部路径、未批准 tag、架构不匹配或只有展示名称的版本不得进入可用集合 | 来源身份、版本 tag、架构、资源完整性信息与记录一致 | 来源不可用时保持已有有效版本；不得以系统 Wine 静默替代并报告 `WineReady` |
| MiPlay 托管安装 | 资源取得、完整性验证、安装和持久化提交全部完成；安装后的运行时身份可复核 | 下载完成、解压完成、目录存在或进度达到 100% 但提交/复核失败，均不得视为安装成功 | 安装结果、持久化记录、运行时路径和版本身份的后置读取 | 失败时清理临时/不完整内容；保留上一有效选择，否则当前游戏为 `NoSelectedRuntime` 或 `SelectedNotReady` |
| MiPlay 运行环境准备 | 托管 Wine 能准备 MiPlay 管理的有效运行环境，并通过启动前置验证 | `wine --version` 成功但 prefix/bottle 不可用、缺少基础目录或前置验证失败，不得进入 `WineReady` | 新环境准备结果、基础目录存在、启动前置检查和实际资源对应关系 | 准备失败不改变为 Ready；记录失败原因，允许重试或重新选择有效托管版本 |
| 本机/第三方 Wine | **无产品能力** | 不检测、不展示、不导入、不复用；发现路径存在不能形成任何通过结论 | 不产生外部 Wine 产品事实 | 不改变 MiPlay 状态；无 MiPlay 托管版本时当前游戏为 `NoSelectedRuntime` |
| 选中版本一致性 | 选中的版本是已安装、已验证、MiPlay 托管的版本，且记录与路径一致 | 记录丢失、路径被替换、来源不明、架构不符或验证过期，不得启动 | 选中记录、安装记录、路径身份和后置验证一致 | 取消选中或 readiness 失效时为 `NoSelectedRuntime` 或 `SelectedNotReady`；不得降级到任何外部 Wine |

本矩阵定义的是当前版本 Product 验收目标，不代表当前网络/Wine 用户验证已经通过。GitHub 请求超时以及 Wine 资产只下载约 5.75 MB / 417 MB 后超时，均不能形成成功证据。任何下游文档或实现中“无托管版本时回退系统 Wine”或“展示外部 Wine 诊断”的口径均不得覆盖本 Product 决策。官方游戏安装、自定义启动参数、帧率解锁和截图/视频入口仍不进入本轮范围。

## 3. 产品边界（Product Boundaries）

**MiPlay 明确不做以下事情：**

1. **不做兼容方案的外部信息源依赖** — 兼容方案本身的定义（操作步骤、条件判断、风险等级等）直接内置在程序中，不依赖外部网站、论坛或社区平台实时获取。**兼容方案不是独立更新对象，而是产品版本的一部分**——所有兼容方案（包括 Wine 默认配置、DXMT 配置、启动参数、兼容性修复等）均随 MiPlay 版本一起发布，不提供在线热更新。当 macOS 或游戏版本发生重大变化导致兼容方案需要调整时，用户需要更新 MiPlay 以获得新方案。此限制不适用于以下两类内容：(a) Wine 运行时版本，可从本文件 2.6 节的批准上游来源获取并由 MiPlay 托管；(b) 展示性内容（如游戏官方公开视觉素材），可从官方公开渠道获取。
2. **不做兼容性预测** — MiPlay 不预测某个系统版本或游戏版本是否兼容，仅在用户尝试启动失败后提供内置已知方案的尝试途径。
3. **不做游戏安装包托管** — MiPlay 不缓存、存储或提供游戏客户端安装包文件；安装过程通过官方资源完成。
4. **不做反作弊程序文件破解** — 兼容方案不修改、不绕过反作弊程序的文件本体，仅利用已知的旧版本替换（非破解性）等手段。
5. **不做游戏内画质与图形调优** — 除 Metal HUD、Retina Mode 和分辨率选项外，所有画质和图形设置在游戏内自行调整。
6. **不做游戏数据的生命周期管理** — 不关心游戏存档、资源包、更新包的内容，不主动管理游戏文件的生命周期。
