## 2. 逐项结论

### I-1 背景缓存指纹

实现与 ADR 031 / Service Contract 基本一致：

- 指纹 `.background-fingerprint.json` 位于媒体缓存目录，包含 source identity、组顺序、各组资源身份与版本，不包含选中或预览态。
- 只有持久化指纹变化时按 diff 清理；指纹缺失不清理。
- 用户切换背景组不删除其他分组缓存，有测试覆盖。
- API 请求失败保留缓存与指纹。

发现：`refreshCache` 仍使用 `lastCachedBackgroundIds` 作为手动清理依据，与“仅兼容诊断字段、不再作为缓存失效依据”的文档表述不一致，登记 P2-I1-01。

### I-2 / I-3 圆点 hover、预览与位置

实现符合冻结 UI/UX：

- 默认 `opacity 0` 且 `allowsHitTesting(false)`；顶部 `40pt` 悬停区或键盘焦点显示。
- `top: 12pt`、命中框 `24 x 24pt`、间距 `10pt`、hover 放大 `1.2x`。
- 预览走独立 `BackgroundPreviewState`，不写 AppData，不改变 `selectedBackgroundGroupID`，不触发缓存清理；测试确认预览后持久化与缓存不变。
- 提交选择前结束预览；仅一个有效组时不渲染圆点。

风险：预览失败/取消的缓存保持与资源身份变化的指纹清理尚无自动化测试，登记 P2-COV-01。

### I-4 Wine 全局 / 单独

主体闭环成立：

- AppData schema 3，`PerGameSettings.wineVersionOverride` 可空；schema 1/2 迁移保留全局默认，不自动生成覆盖。
- `effectiveVersion(for:) = override ?? global`；覆盖无效不静默回退，有测试。
- `PreLaunchValidator`、`LaunchOrchestrator` 均使用 `validatedRuntime(for: game.id)`；无 Game 上下文的 `checkReadiness()` 不产生 `WineReady`。
- Settings 提供“全局 / 单独”作用范围、固定三款游戏菜单、移除覆盖入口；作用范围不写业务字段。
- 删除保护检查全局默认、全部 per-game 覆盖、活动下载；per-game 引用删除保护有测试。

发现：删除保护只检查 `kind == "wineInstall"` 的未收敛恢复记录，未覆盖 `wineDelete` 等全部未收敛恢复记录，也未检查独立 RecoveryGuard；与 ADR 034 / Service Contract 的“未收敛恢复记录”要求不一致，登记 P1-I4-01。

### I-5 此 Mac

主层级信息正确：

- 机型取 IORegistry `product-name`，本机解析为 `MacBook Pro`。
- 芯片取 `machdep.cpu.brand_string`，本机为 `Apple M1 Pro`，不再使用 `hw.model`。
- 内存使用系统物理内存并格式化为可读文本；通用设置展示机型、芯片、内存、macOS 版本四行，Wine 目标磁盘独立。
- 空字符串由 UI 显示“未知”。

发现：`SystemInfo` 与 ADR 036 / Service Contract 仍存在命名和字段缺口：实现字段为 `chipModel` 且没有 `modelIdentifier`，契约要求 `chipName` 与 `modelIdentifier`。登记 P2-I5-01。
